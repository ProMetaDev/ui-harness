# 文档安全编辑

用于 Markdown、HTML、DOCX、PPTX、XLSX、ODT、PDF 等文档的修改。
核心不是“把内容改对”，而是**改完之后原件的结构、样式、关系和可打开性都还在**。

## 0. 先判断：这是哪一种文档

| 类型 | 允许的编辑方式 | 禁止 |
|---|---|---|
| `.md` / `.txt` / `.html` | 复制后按原文做**局部 patch** | 整篇重写、自动格式化 |
| `.docx` / `.odt` | 复制后用 OOXML/ODT 结构编辑，或只改文本节点 | 用 `fs_write` 重建整个文档、Pandoc 往返 |
| `.pptx` | 复制后只改已有文本框/段落 | 删除母版、重建 slide、整页替换 |
| `.xlsx` | 复制后只改目标单元格/公式 | 重建工作表、丢掉样式/透视/图表 |
| `.pdf` | 复制后叠加批注/覆盖层 | 重排文字、整份重生成 |

不确定时按二进制处理：只复制，不编辑。

## 1. 建立工作副本（强制）

1. 先读原件，记录：
   - 绝对路径；
   - 字节数、mtime；
   - `sha256`。
2. 在**原文件同目录**创建副本：
   - `<stem>.edit-<YYYYMMDD-HHMMSS>.<ext>`
   - 同目录是为了让相对图片、附件、模板关系继续成立。
3. 后续所有修改只发生在副本上。
4. 原件在交付前保持字节不变；用第 5 步再次核对哈希。

不要用“新建一个同名文件再覆盖”的方式编辑；那等于重写原件。

## 2. 先理解结构，再动内容

读原件时至少确认：

- Markdown：frontmatter、标题层级、列表、表格、链接、代码围栏、空行；
- HTML：DOM 树、class/id、内联样式、script/style；
- DOCX：段落、表格、图片、页眉页脚、样式、节、编号；
- PPTX：slide 数、母版/版式、占位符、文本框、图片；
- XLSX：sheet 数、合并单元格、公式、样式、图表；
- PDF：页数、是否有表单/批注/附件。

先写一句“我要改哪几个结构节点”，再动手。不要边改边猜。

## 3. 最小编辑

### Markdown / 文本 / HTML

- 用 `patch` 或 `fs_edit` 改**最小连续片段**；
- 保留原有标题级别、列表符号、缩进、空行、表格对齐、链接写法；
- 保留 frontmatter、BOM、CRLF/LF、文件末尾换行；
- 不要顺手“整理格式”、不要重排表格、不要改引用链接；
- 一次只改一个逻辑块，改完立即 diff。

### DOCX

- 优先只改 `word/document.xml` 中已有的 `<w:t>` 文本节点，保留 `<w:r>`、样式、书签、域代码；
- 需要插图表/复杂结构时，用 `python-docx` 在副本上操作，保存后检查是否有内容丢失；
- 不要从零 `Document()` 重建再粘贴正文；那会丢样式、编号、页眉页脚；
- 不要用 Pandoc 把 DOCX 转 Markdown 再转回来。

### PPTX

- 只改已有 shape 的 text frame；保留 layout、master、theme；
- 不要删除再新建 slide 来“替换内容”；
- 保存后核对 slide 数、图片数、占位符数。

### XLSX

- 只改目标 sheet 的目标单元格；公式保持公式；
- 不要整表读成值再写回；那会丢公式、格式、合并单元格、图表；
- 保存后核对 sheet 数、公式数、合并区域。

### PDF

- 只做 overlay/annotation/redaction；
- 不要试图重排正文；重排必然破坏原版面。

## 4. 校验（改完必须做）

至少跑这四类检查：

1. **原件未变**：`sha256` 与第 1 步一致；
2. **副本可打开**：
   - DOCX/PPTX/XLSX：`unzip -t` 通过；能解析 XML；
   - PDF：页数可读；
   - Markdown/HTML：能按原编码读出；
3. **结构守恒**：
   - 标题/表格/图片/代码块数量不减少（除非用户明确要求删）；
   - DOCX 段落/表格/图片数、PPTX slide 数、XLSX sheet/公式数不减少；
4. **视觉/内容抽查**：
   - 文本 diff 只包含预期改动；
   - 有条件时用 LibreOffice 转 PDF/PNG 抽查第一页和改动页。

任何一项失败：**保留原件，停止交付**，报告哪一项没通过。

## 5. 交付与替换

默认只交付副本：

```
原件：<path>（sha256 未变）
副本：<path>.edit-...（已修改）
校验：结构守恒 / 可打开 / diff 只含 N 处
```

只有用户明确说“替换原件”时才：

1. 先把原件移到 `<stem>.bak-<timestamp>.<ext>`；
2. 再把副本原子移动到原路径；
3. 报告备份路径和新的 sha256。

不要默认覆盖，也不要在用户没确认时删除副本或备份。

## 6. 停止条件

出现以下情况立即停，不要“修到能跑”：

- 原件哈希已经变了；
- 副本打不开，或 XML/zip 损坏；
- 结构计数减少且不是用户要求的删除；
- 只能靠整篇重写才能完成；
- 需要安装重依赖/联网才能校验，而用户没有授权。

## 7. 输出模板

```
改动文件：<original> → <copy>
改动位置：<章节/段落/单元格>
结构检查：标题 x→x，表格 x→x，图片 x→x（或 slide/sheet/公式）
原件哈希：<sha256>（未变）
校验结果：通过 / 失败原因
是否替换：未替换（等待确认） / 已替换，备份在 <path>
```
