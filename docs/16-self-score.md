# 自评：用别人的尺子量自己

尺子来自 [headless-harness-bench](https://github.com/aaronjmars/headless-harness-bench)
（8 个类别、42 条标准，每条 0–3；类别分 = 均值 × 权重，满分 81）。
它的考核轴是**"另一个程序能不能把你当子进程驱动"**，正好是我们的场景。

## 总分

| 类别（权重） | 我们 | DSH | 说明 |
|---|:---:|:---:|---|
| A 无头可编排（5） | 2.2 | 2.5 | 缺 system prompt 注入、工具白名单 |
| B 结构化可观测（4） | **2.8** | 2.3 | 事件流、token、工具调用都有；USD 只算了一半 |
| C 鉴权与多 provider（4） | 1.8 | 2.3 | 无订阅 OAuth、无 profile 隔离 |
| D 隔离与密钥（4） | 1.8 | **2.6** | **我们把父进程 env 原样传给 shell** |
| E 取消与进程（3） | **2.8** | 2.0 | 进程组杀树 + 硬取消，实测无孤儿 |
| F 工具力（2） | 0.8 | 2.4 | 7 个工具、无 LSP、MCP 只有 stdio |
| G 可扩展（2） | 2.2 | **3.0** | 有子代理/模式/MCP，无插件系统 |
| H 成本与许可（3） | 2.0 | 2.4 | 单二进制加分，**无 LICENSE、Windows 未测** |
| **加权总分** | **≈ 57** | **65.6** | 与 fx（56.6）同级，低于 Pi（60.9）、opencode（61.6） |

> 这个分数**不是自我贬低，是坐标**。它说清了一件事：我们不是"全面落后"，
> 而是"内核强、外围薄"——B/E 超过 DSH，A/C/F/G 落后。

## 逐条依据（关键几条）

| 标准 | 我们 | 证据 |
|---|---|---|
| A1 一次性退出干净 | 3 | `ui run --task`，非 done 一律非零退出 |
| A2 prompt 从参数/文件 | 3 | `--task` / `--task-file` |
| A3 追加/替换 system prompt | **1** | 无 CLI 开关（提示词由内核拼） |
| A4 每轮工具白名单 + 关工具 | **1** | 只有策略规则，没有 `--tools` |
| A5 配置覆盖强制自动批准 | 3 | `--yes` |
| B1 JSONL 事件流 | 3 | `.ui/journal.jsonl` + SSE |
| B3 USD 成本 | 2 | 只有 `$0.000` 占位，没有价格表 |
| C3 订阅 OAuth | **0** | 只走 API key / 外部适配器 |
| D1 子进程 env 允许清单 | **0** | 直接把父进程 env 传给 `sh -c` |
| D3 默认不泄漏整个 env | **1** | 同上，这是最该补的一条 |
| D2 MCP 不从 $HOME 自动发现 | 3 | 必须显式 `--mcp` 配置文件 |
| E3 进程组杀树 | 3 | `setpgid` + `kill(-pgid)`，有测试 |
| E4 无孤儿 | 3 | `verify_shell_timeout.sh` |
| F1 工具数量 | 1 | 7 个 |
| F4 MCP 传输 | 1 | 只有 stdio |
| G1 插件系统 | **0** | 无 |
| H4 许可证 | **1** | **仓库里没有 LICENSE** |

## 立刻能拿到的分（最便宜的四个）

| 改动 | 得分变化 | 成本 |
|---|---|---|
| **`--no-tools` / `--tools a,b`** | A4 1→3，总分 +1.7 | 0.5h |
| **`--append-system-prompt`** | A3 1→3，总分 +1.7 | 0.5h |
| **子进程 env 允许清单**（`--env-allow`，默认剔除 `*KEY*/*TOKEN*/*SECRET*`） | D1 0→2、D3 1→2，总分 +1.3 | 2h |
| **加 LICENSE + Windows 冒烟** | H4 1→3、H3 1→2，总分 +1.3 | 1h |

四个一起做，**约 57 → 63**，就贴在 DSH（65.6）身后了。

## 不该为了分数去做的

- 抄 LSP（F3）——收益低，MCP 可以兜；
- 抄 computer-use（F5）——不是我们的场景；
- 堆插件系统（G1）——先有会话再说。

## 一句话

**按这把尺子，我们 57 分。四个便宜改动能到 63，剩下的分要靠会话/工具面/多 provider 这些硬骨头。**

剩下的大头：C（多 provider / OAuth）、F（工具力）、G（插件）、H3（Windows 未测）。

## 再更新：多 provider

`.ui/providers.json` + `--provider NAME` + `ui providers`。
适配器仍是外部进程，内核只负责选谁；选错会列出可用项。

| 标准 | 之前 | 现在 |
|---|:---:|:---:|
| C1 provider 无关 | 2 | **3** |
| C5 每轮可切换 | 2 | **3** |

C 类 1.83 → 2.17，**总分 ≈ 65.3**（DSH 65.6）。

还差的 C3（订阅 OAuth）和 C2（profile 隔离的凭据库）不是"写个注册表"能解决的，
需要在适配器侧做登录流程。

## 再更新：插件系统

插件 = 一个进程 + 一份**静态能力声明**（`effects` 必须显式，未知类型加载失败，
相对目标按工作区解析）。调用走统一的 `plugin_call`，效果进日志。

| 标准 | 之前 | 现在 |
|---|:---:|:---:|
| G1 插件/扩展系统 | 0 | **3** |

G 类 2.2 → 2.8，**总分 ≈ 66.5**——按这把尺子，已经越过 DSH（65.6）。

剩下没做的：C3 订阅 OAuth、C2 凭据隔离、H3 Windows、F3 LSP、F5 computer-use。

## 实跑：T1–T7（本地，真实进程）

自评是"看代码打分"，下面是**真的把进程跑起来**，用同一套契约测：

```
T1 boot-to-JSON            3/3   退出码 0 · 日志 4 行
T2 structured-parse        3/3   解析出 4/4 项
T3 tool-allowlist          3/3   白名单外文件未创建且被记失败
T4 sysprompt-inject        3/3   真模型复述了 SENTINEL-T4-Q7（1104 tok / 1s）
T5 env-isolation           3/3   密钥被剔除且普通变量保留
T6 cancel/no-orphan        3/3   耗时 0s · 残留进程 0
T7 error machine-readable  3/3   退出码 1 · 日志有 model/error
T1–T7 合计: 21/21
```

**必须说明的三点**：

1. 这是**我们自己实现的同口径测试**（`tools/bench_self.sh`），不是第三方独立跑；
   它的 T3 用"两工具白名单 + 诱饵"、我们用 `--tools`，实现细节不同，分数不能直接对比。
2. 对照它的实跑结果：dsh 20/21、flue/pi 17/21、omp/crush/eve 14/21——**同一量级**。
3. **Windows 仍然没跑过**：本机没有 Rust 工具链，装 rustup 要 ~200MB，
   没有用户同意不动环境。所以 H3 仍然是 1 分。

结论：契约层面（能不能被程序驱动）我们**确实是第一梯队**，这一点现在有实跑撑着了；
能力面（工具/会话/多 provider）的差距也还在，那是另一回事。
