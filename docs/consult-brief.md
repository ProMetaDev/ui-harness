# 请审阅「ui」：一个审计优先的 agent harness

请以一个**挑剔的技术负责人 + 投资人**的双重视角读这份简报。我不需要鼓励，需要判断和反驳。

## 事实（都可验证，不是愿景）

- **形态**：单二进制 + 单文件网页，Rust 内核，**零第三方 crate 依赖**（不能用 crates.io），约 13.5k 行；命令行 20 个子命令。
- **核心主张**：每一步都能解释。日志是**追加式 JSONL + SHA-256 哈希链**，记录"效果集 + 策略判定 + 是否批准 + 结果"，可 `verify`、可重放、可在崩溃后对账（多进程并发追加已做 flock + 补尾）。
- **权限模型**：效果集（`fs.read/fs.write/proc.exec/net.fetch/secret.read`）+ 最长字面前缀匹配 + allow/ask/deny；批准只对**字面目标**生效（批准 `echo *` 不会放开 `echo pwned`）；真实路径校验防符号链接越界；shell 在独立进程组，超时杀整棵树。
- **三种模式**：quiet / standard / strict，只改严格度不改日志格式；`deny` 是硬边界。因此能**事后重判**：`ui audit --as strict` 用严格模式重跑历史，告诉你哪些动作当时会被拦。
- **多智能体**：`ui team --task "..."` 让模型用 `plan` 工具拆任务 → 生成 workflow → 并行隔离副本执行 → 自动 apply（冲突/漂移双闸）→ **验收命令**（`--accept`，失败则非零退出）→ 汇总（只看磁盘，不看子代理自述）。
- **科研链路**：`ui lab pack/verify/table/claim` 产出可复现实验包（产物哈希 + 输入血统 + 环境指纹 + 结论对账）；数据版本不一致时拒绝求均值。
- **扩展**：MCP（stdio）与本地插件，插件必须**静态声明 effects**，未知效果类型加载即失败。
- **质量**：131 个测试、35 项门禁（含 Windows 回归）、真模型跑通（DeepSeek）。
- **横向基准**：别人用同一把尺子（headless-harness-bench，42 条标准/81 分）给 9 个 harness 打分，DSH 65.6；我们自评 ≈67.5（**自己打分，可能偏乐观**）；自实现的 T1–T7 契约测试实跑 21/21（**尺子是自己做的**）。
- **实机**：Linux（WSL）与 Windows 都跑过；Windows 上真模型、网页端（token 鉴权/Cookie/SSE）均通过。Windows 上仍有一个未解：用户临时目录不可写（os error 5），doctor 如实告警并降级。

## 约束

- 单人开发，没有云、没有 GPU；Windows 主机 + WSL2。
- 不做 UI 框架、不加依赖、不引入 node/npm 运行时依赖（适配器除外）。
- 已有真实用户场景：我自己做实验/写代码；尚未给别人用。

## 已完成的取舍（请质疑这些取舍本身）

1. **不做 OS 沙箱**（只有工作区边界 + 效果策略），DSH 有 bwrap/Landlock/Seatbelt。
2. **不做 LSP、不做 computer-use**，理由是"收益低/与可审计冲突"。
3. **不追功能数量**，13 个工具（含 MCP/插件网关），DSH 20+。
4. **记忆（memory）没做**，认为它是会话的延伸。
