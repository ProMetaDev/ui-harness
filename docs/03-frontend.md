## 网页端 V2：飞行记录仪（2026-11）

`ui serve` 的网页端从「通用聊天 + 小账本」换成了「对话日志 + 当前步仪表」：

- **壳**：60px 活动栏 / 272px 侧栏 / 主区 / 340px 右栏 / 26px 状态栏；1300 以下右栏折成 **52px 仪表条**（保留 step / 状态），900 以下侧栏收起；
- **顶部**：会话名 masthead + 工作区路径 + `Ctrl K` 命令入口 + 模型 / 模式 chip；侧栏标题退成弱标签；
- **日志**：时间 / 角色（YOU / AGENT / TOOL / SYS）共用一条时间线；用户消息带左侧琥珀线，工具调用两行（身份 + 结果），**去卡片化**，只留 1px 左轨，点开看全文；
- **字阶**：10.5 / 11.5 / 13.5 / 15，消灭 9px 正文；间距按 4/8/12/16/24 的节奏；
- **右栏**：快照分段条 + 决策时间线 + 账本 + 审批队列；数据来自内核 SSE 的 `snapshot` / `decision` 事件，不是前端猜的；
- **审批**：固定在输入框上方，不随对话滚走；参数默认折叠，按钮带 `Y/A/N`；
- **空状态**：Pre-flight + 三个真实入口 + workspace readiness；
- **主题**：暗色炭黑 + 单琥珀；明色暖纸；`auto` 跟随系统；
- **动效**：日志逐条上浮、分段条生长、决策点弹出、审批条上浮、盖章；系统 `prefers-reduced-motion` 时全部关闭；工具行可键盘展开。
- **顺滑**：流式 delta 按帧合并、滚动用 `requestAnimationFrame` 合并、右栏决策只让**新增项**入场、分段条只在首帧生长、工具展开做高度过渡、审批退场 160ms——避免“每来一个事件整块重绘”的卡顿。
- **树结构**：右栏是一条 spine：`ctx / dec / bud / gate` 四个分支，context 的子段是叶子；主日志每条消息是时间轴上的节点；实验室保留表格/DAG 的血缘阅读。树只做结构提示，不替代正文。

验收截图：`out/web-tree-final.png` / `web-tree-final-1280.png` / `web-final-empty.png` / `web-final-light.png`。

### 信息架构

一句话：**全局导航只有 4 个真入口，侧栏只放当前上下文的列表，低频操作全部进 masthead 的 `⋯`。**

| 层 | 放什么 | 不放什么 |
|---|---|---|
| 活动栏 | 对话 / 工作区 / 能力 / 实验室 | 未完成的“自动化”入口已移除 |
| 顶部 masthead | 会话名 / 路径 / 命令入口 / 模型 / 模式 / `⋯` | 低频开关 |
| 侧栏 | 会话、文件树、工具与技能、实验包 | 预算、模式、停止、导出 |
| 右栏 | 当前步：上下文分段 / 决策 / 预算 / 审批队列 | 模型与模式的重复展示 |
| 输入区上方 | 审批 | 历史审批 |
| `⋯` 菜单 | 新建会话、导出快照、显示 UU、右栏、外观 | 高频操作 |

约束：**同一个能力只有一个主入口**。模式主入口在 masthead（状态栏 pill 只是快捷翻页）；
停止只在输入区；预算主入口在右栏；导出/外观/看板娘在 `⋯`；侧栏不再承担设置。

## 网页端 `ui serve`

```bash
ui serve --port 7788 --workspace demo
# 浏览器打开 http://127.0.0.1:7788/
```

零依赖：HTTP 解析、SSE 推送、审批回执全是 std 手写，一个二进制搞定。

| 端点 | 用途 |
|---|---|
| `GET /` | 对话页（单文件，内嵌 CSS/JS） |
| `GET /api/events?since=N` | SSE：只补 `seq > N` 的事件（断线重连不重放历史），15s 心跳 |
| `POST /api/say` | `{"text": "..."}` → 交给工作线程跑一轮 |
| `POST /api/approve` | `{"verdict": "allow"\|"always"\|"deny"}` |
| `POST /api/cancel` | 停止正在跑的轮次（令牌直达模型适配器与 shell 进程组） |
| `GET /api/tool/<id>` | 某次工具调用的**完整输出**（列表里只发一行摘要） |
| `GET /api/state` | `{"busy": bool, "seq": N}` |
| `GET /snapshot` | 静态快照：事件内嵌、不开 SSE，可分享/离线/截图 |

界面上的四件事：

- **停止按钮**：只在运行中出现，点击即打断（实测 250ms 生效；审批等待里也有效）；
- **工具行可点开**：默认一行摘要，点一下按 id 拉全文，再点收起；
- **时间戳**：每条消息右侧有 `HH:MM:SS`，流式的临时气泡在最终文本到达时校正；
- **自动滚动只在底部发生**：翻历史时不会被新事件拽走。

设计取舍：

- **一次只跑一轮**：`busy` 期间消息排队（`mpsc` 串行），避免两轮抢同一份历史；
- **审批不替你决定**：浏览器 300 秒不响应按拒绝处理，宁可卡住；
- **快照页只读**：用于发给别人看"这一轮怎么跑的"；
- **页面状态全部来自事件流**，没有前端状态机；刷新靠服务端补发历史。

已知边界：单用户、无鉴权、只绑 `127.0.0.1`。

## 开机界面

交互式启动时放一遍，**每一格都是真实检查**（`GET /api/ready`），不是定时器：

```
U:I
Unleash your imagination

INITIALIZING UI  ▮▮▮▮
config     model scripted    2ms
journal    10 条事件 · 链完整  8ms
skills     2 个 skill       10ms
workspace  /path/to/demo     1ms
OK
                                  任意键跳过
```

| 规则 | 行为 |
|---|---|
| 出现时机 | 每次交互式启动；`--no-splash` 或 `UI_SPLASH=0` 或非 tty（脚本/CI）不放 |
| 最短停留 | 约 700ms（逐步点亮，每步 130ms），避免闪一下 |
| 跳过 | 任意键 / 点击 / Esc，立即淡出；SSE 已在后台连接，不丢事件 |
| 失败 | 停在失败那一步：红字 + 原因 + 「继续（受限模式）」「看日志」 |
| 降级 | journal 打不开就用临时日志，顶部常驻「受限模式」提示 |
| 终端版 | TUI 里同一套检查印在滚动区（不占全屏），`--no-splash` 同样生效 |
| 截图 | `/snapshot?splash=1` 渲染开机页（静态、无 SSE），方便出设计图 |

**做不到的事不画格子**：格子数 = 检查项数，失败的那格不点亮。

### 动画序列（约 2.6s，节奏跟着真实耗时走）

| 时间 | 动作 |
|---|---|
| 60ms | `U` 从左侧滑入 |
| 240ms | `I` 从右侧滑入 |
| ~660ms | **相撞**：I 压过去 3px、U 顶 2px，整块抖两下（±2px、1.02 倍） |
| 740 / 820ms | 冒号被「撞出来」：两点依次弹出 |
| 900ms | 一道扫描光从左扫到右 |
| 1080ms 起 | 逐条点亮检查项，每步至少 260ms（慢的步骤按真实耗时走，不假装快） |
| 结束 | 一行真实遥测（`tools 6 · budget 200k tok` + 闪烁光标）→ `OK` → 停 560ms 淡出 |

**自适应**：每步停留 = `max(260ms, 真实耗时 × 0.8)`。所以机器慢、日志大、技能多的时候，
动画会跟着变长——它显示的是真实进度，不是固定动画。

深链：`?view=lab&report=lr-s2`。

**「跑一次基准」**：服务端用 `--bench-cmd <命令>` 指定要跑什么，点按钮 → `POST /api/lab/run`
→ 后台执行 → SSE 推 `lab-run{phase:start|end, code, ms}` → 页面刷新列表。

## 看板娘 UU

它就是 `U:I` 里那两个点。开机动画里 U 和 I 相撞撞出冒号，UU 从冒号的位置睁眼——
所以它不是贴上去的吉祥物，是从品牌符号里长出来的。

| 状态 | 表现 | 触发 |
|---|---|---|
| `idle` | 每 4 秒眨一次眼 | 空状态 |
| `thinking` | 眼睛变成转圈的环 | 运行中 |
| `happy` | 眼睛变 `^ ^`，1.6s | `reason === "done"` |
| `error` | 眼睛变 `× ×`，3s | 出错 |

**出现位置只有三处**：开机画面（logo 旁）、空状态（U:I 旁）、输入框左侧。
活动栏、审批卡片、错误提示旁边都不放——这是个"敢让它碰生产"的工具，严肃时刻不能卖萌。

**非 done 不笑**：失败就是失败。

侧栏「显示 UU」可关，选择记在 `localStorage`；`prefers-reduced-motion` 时只保留状态切换、不眨眼不转圈。

实现是纯 SVG + CSS，零图片资源。三个踩过的 CSS 边界：

1. SVG 里做 `transform-origin: center` 必须先设 `transform-box: fill-box`，否则原点按画布算，眨眼会变成"飞走"；
2. 转圈用 `stroke-dasharray="9 30"` + `rotate` 就是一个缺口环，不需要切图；
3. 状态用 `data-mood` + 属性选择器切换，**JS 里没有一行动画逻辑**。

## 流式输出

模型回复现在是逐段出现的，不是等整段返回。

**协议**（适配器 stdout，一行一个 JSON）：

```
{"delta":"流"}
{"delta":"式"}
{"delta":"你好"}
{"content":"流式你好","toolCalls":[...],"usageTokens":12}   ← 最后一行才是结果
```

- 内核 `Model::respond_stream` 有默认实现（把整段 content 回调一次），所以假模型不用改；
- `ExternalModel` 逐行读子进程 stdout，`delta` 只用于展示，**最终结果只认最后一行**；
- 没有逐行协议时自动退回「整个 stdout 是一个 JSON」的老格式；
- SSE 侧：`{"type":"delta","text":"..."}`，结束后照旧一个 `{"type":"assistant","text":"完整文本"}`。

**一个关键细节**：模型被要求输出 JSON 协议，如果直接把原始增量推给界面，用户会看到
`{"content":"流…`。所以适配器做了**增量提取**：只把 `content` 字段里新出现的可见文本推出去，
转义和 `\uXXXX` 都处理了（没收全就等下一段）。离线探针断言两件事——"delta 里不能出现
JSON 括号"、"所有 delta 拼起来等于完整 content"。

**未实测**：真实 `api.deepseek.com` 的 `stream:true` + `response_format:json_object` +
`stream_options.include_usage` 三者组合（离线假服务验证了链路，但没花真钱）；真实网络下的
延迟、断流、背压；原生 `tool_calls` 分片（设计上不依赖）。

**还没做**：TUI 没实现 `on_delta`（网页端先享受到了）；网页端仍**不能取消**正在跑的轮次。

## 结论：A 的骨架 + B 的右栏

| | A（炭黑） | B（纸白） |
|---|---|---|
| 气质 | 终端原生、信息密度高 | 规格书、冷静、可读 |
| 骨架 | 三栏：会话 / 对话 / 预算账本 | 双栏：对话 / 当前步 |
| 右侧内容 | 四条预算条（tokens/calls/wall/cost） | 快照分段（bytes+tok）+ 决策时间线 |
| 问题 | 右侧只讲钱，讲不了"这一步发生了什么" | 左侧没有会话历史 |

**取 A 的暗色与三栏骨架，右侧换成 B 的"当前步"**——因为我们的契约 1（分段快照）和契约 3
（效果决策）是核心，光看预算条看不出这两件事。预算条可以缩成右栏底部两行。

| 角色 | hex | ANSI-256 | 用途 |

| 分隔线 | `#2a2d24` | 238 | 1px 细线，不用阴影 |

规则：强调色**只允许出现在一处**（当前焦点）；其余一律灰阶。这条比配色本身重要。

## 版式规则

1. **8 列定宽标签**：`[user] `、`[agent] `、`[tool]  `、`[warn]  `。终端里 CJK 前缀会让列歪，
   所以标签必须是纯 ASCII。
2. **工具调用占两行**：第一行 `name [ok|error]`，第二行缩进 8 列写结果摘要（`→ …`）。
   一行塞不下"做了什么"和"结果是什么"。
3. **审批浮层不透明**：`Effect:` 与 `Args (preview):` 分段，底部三个键 `[y] [a] [n]`；
   永远显示效果再显示参数——先看"会发生什么"，再看"用什么参数"。
4. **右栏（≥100 列才出现）**：上方快照分段（id / tok / B），下方决策时间线；
   底部两行压缩预算。窄于 100 列时右栏收起，预算回到底部状态行。
5. **顶部一行身份**：`U:I  v0.1.0  ·  Unleash your imagination  ·  ws: …`。

## 轨迹查看器（`ui export --html`）

单文件、数据内嵌、无外链，双击即看。设计参照主流后台应用（Linear / Vercel / shadcn 一类）：

| 约定 | 做法 |
|---|---|

| 交互 | hover 变底色、选中项强调底色、`↑↓/jk` 切步、`Esc` 不劫持、`:focus-visible` 焦点环 |
| 细节 | 代码块 hover 出现"复制"、表格数字右对齐等宽、空状态有文案 |

## 怎么用

```bash
# 1. 生成（导出当前 workspace 的日志）
$HOME/ui-target/release/ui export --workspace demo --html out/trace.html
# → 已导出 /mnt/x/.../out/trace.html
# → Windows 路径 X:\dsh_ws\harness-v2\out\trace.html

# 2. 打开：双击那个文件，或把 Windows 路径粘进浏览器地址栏
```

界面三栏：

- **左：步骤**。状态点（绿=正常、红=有失败、橙=待批准）+ 时间 + 一句话摘要。`↑↓` 或 `jk` 切步，点击也行。
- **中：这一刻的现场**。提示快照（四段各占多少 bytes/tokens）、模型输出、参数修复、工具调用（工具 / 效果 / 决策 / 结果）、原始参数 JSON。点工具行切换看哪一次的参数。
- **右：账本**。末步快照 tokens 与上限、工具调用数、墙钟、事件数，以及各工具被调用几次。

顶栏：`主题` 循环 自动/浅/深；`复制日志` 把整份事件 JSON 放进剪贴板。想固定配色可以在地址后加 `?theme=dark`。

### 拿它查什么

| 症状 | 看哪里 |
|---|---|
| 模型没干活 / 没调工具 | 该步 `工具 0`，看"模型输出"说了什么 |
| 为什么被拦 | 工具调用行的决策 chip（deny 红 / ask 橙），"效果"列写着目标 |
| 钱花在哪 | 快照表哪一段 tok 最多；右栏对比历史步 |
| 参数怎么坏的 | "参数修复"卡片：第几次、哪个工具、什么错 |
| 崩溃过没有 | 工具行"结果"显示"未执行" → 回终端跑 `ui verify` / `ui resume` |
| 两步差在哪 | 分别点开两步，比对快照表的 tok 与模型输出 |

### 注意

导出的是**快照**，不是实时界面；日志更新后要重新导出。
文件自带数据、无外链，可以直接发给别人——这是它相对 TUI 的主要优势。

## 右栏「当前步」

宽终端（**≥100 列**）里，正文右侧出现一条 34 列的竖栏，回答"这一步模型看到什么、
为什么放行/拦截、账本还剩多少"：

```
 当前步 3 · 1719 tok
──────────────────────────────────
 快照 8f2a1c7d9e0b4a
 core    kernel   520 tok
 env     kernel    96 tok
 tools   tools    340 tok
 history session  763 tok
──────────────────────────────────
 决策
 allow fs_read  读取 demo/greet.js
 allow fs_edit  编辑 demo/greet.js
 ask   shell    执行 cargo test
──────────────────────────────────
 账本
 tok 1719/200000
 calls 3/60
 0s · $0.000
```

| 规则 | 行为 |
|---|---|
| 出现条件 | 宽度 ≥100；**99 列不出现**，不挤压正文 |
| 数据来源 | `Hooks::on_snapshot` / `on_decision`（内核在写日志的同一处回调，不是 UI 自己猜） |
| 一轮一清 | 每条新消息开始，右栏清空成"等待第一步"，不混上一轮的决策 |
| 决策状态 | `ask` 在用户按 `y/a/n` 后原地改成 `allow`/`deny`，不新增一行 |
| 放不下 | 决策从最旧的开始丢，并明写「更早 N 条」；**账本贴底**，不被长列表挤走 |
| 窄屏 | 整栏收起，正文占满；账本仍在顶部状态行 |

右栏不是"又一个监控图"：它只展示两条契约——契约 1 的快照分段（谁在吃 token）、
契约 3 的决策依据（为什么被拦）。宽度不够时宁可不要，也不做一列挤到看不懂的缩略。

## 已落地

- `frame.rs`：**语义样式**（Normal/Dim/Accent/Warn/Err/AccentStrong）→ 每行由 `Span` 组成，
  颜色不在渲染层硬编码，而是标"这一段是什么语义"；
- **右栏「当前步」**：宽终端显示快照分段 + 决策时间线 + 账本；窄屏自动收起；
- 视觉层次：品牌 `U:I` 强调色加粗、标签 `[user]` 强调、`[agent]/[tool]` 次要、
  `[warn]` 橙、失败调用整行错误色；状态条的预算条按压力变黄/变红；
- 留白节奏：换说话人自动空一行（连续工具调用之间不空），正文与标签分列；
- `term.rs`：256 色 SGR、深色底（234）、擦除前先复位背景；
- `ui preview --ansi` 可在不进 TUI 的情况下看颜色；
- 浮层重画：四角正确（之前左右用同一个角字符）、不透明、居中；
- `ui tui`：备用屏、raw mode、按键队列、`y/a/n` 审批、`j/k` 滚动、干净退出；
- 账本实时更新：内核新增 `Hooks::on_budget`；
- 尺寸纪律：任意 `cols×rows` 下每行恰好 N 显示列（含 CJK 双宽）。
