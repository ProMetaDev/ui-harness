# 协作模式：一个复杂任务，多智能体并行

灵感来自 DSH 的子智能体。核心判断是：**引擎已经够了，缺的是"自动拆解"这一层**。

## 现状：已经有的引擎

| 能力 | 在哪 |
|---|---|
| 并行子代理、各自独立日志 | `workflow` 的 `Node::Group` |
| 隔离工作区副本 | `--isolate`（每个子代理一份拷贝） |
| 改动合并的冲突/漂移双闸 | `ui apply`（退出码 3/4） |
| 每步快照、预算、审批留痕 | 七条契约 |

所以团队模式没有重写执行器，只是加了一个规划层。

## 用法

```bash
ui team --task "把这件事拆开做：写模块 A 和 B" --agents 2
```

流程：

1. **规划**：单独一个 agent（quiet 模式）只输出 JSON：
   ```json
   {"parallel":[{"prompt":"子任务 1"},{"prompt":"子任务 2"}],"summary":"汇总阶段的提示"}
   ```
   容错：`extract_plan` 会从 ```json 围栏或前后废话里抠出第一个 `{...}`。
2. **转格式**：拼成 workflow 认识的形状——第 1 步并行跑所有子任务，第 2 步汇总；
   写到 `.ui/team-<时间戳>.json`。
3. **委派**：调用现有 `workflow` 执行器（默认带 `--isolate`）。

## 实测

```
协作模式 · 目标：把这件事拆开做：写模块 A 和 B
子代理：2 个（并行）
计划：2 个并行子任务
  1. 写一个模块 A 的草稿
  2. 写一个模块 B 的草稿
交给 workflow 执行（并行 + 隔离）…
工作流 team-2 · 2 步 · 3 个任务
── 第 1/2 步 · 2 个并行子代理 ──
  子代理 team-2-s1-1 ok
  子代理 team-2-s1-2 ok
── 第 2/2 步 ──
工作流完成
```

日志里：

```
workflow/start → delegate/end ok ×2 → workflow/step → workflow/end done
```

## 这个模式真正的价值在哪

不是"更多 agent"，而是**把不可审计的大任务切小，让每一步都能单独验证**：
每个子代理有自己的日志、自己的工作区副本、自己的预算；合并时过冲突闸。
出问题时能回答"是哪个子代理、哪一步、改了什么"。

## 真模型实测（2026-11-16）

任务：给 `/tmp/team-real` 补单元测试与 README 用法，2 个子代理，隔离。

**结果**：`test/math.test.mjs` 新增（1758B，8 个用例，8/8 通过）；`README.md` 86B → 879B；
`math.js` 未变（93B）。耗时 179s，**50,938 tokens**，12 步。

**它自己抓出的问题**（原文）：

> 核对发现：子代理自述"已完成 README 更新"，但与磁盘上的实际情况不符 ——
> 主工作区 README.md 仍是 86 字节原文，两个子代理 ws 副本 diff 与原文逐字节相同（无输出）。
> 即该子任务**没有合并回工作区**。

这正是我们要的行为：**汇总阶段不信自述，只看磁盘**。

### 真模型逼出的三个设计缺陷（已修）

1. **模型拒绝输出 JSON**。它在正文里写："harness 的输出结构要求整条回复只能是一个
   `{content, toolCalls}` 对象，不能在 content 中再嵌套 JSON，因此我没有按你给的
   `{"parallel":...}` 结构原样输出"。它是对的——**是我们协议自相矛盾**。
   修法：加一个 `plan` 工具，让它用工具提交；正文不承载结构。
2. **子代理的产出从未合并**。`workflow --isolate` 只在副本里跑，`apply` 是另一条命令。
   修法：`cmd_team` 在 workflow 之后自动 `apply --all`（冲突/漂移闸照旧）。
3. **汇总跑在 apply 之前**，看的是主工作区，于是误判"什么都没做"。
   修法：汇总拆成独立的一轮，放在 apply 之后。

### 仍然存在的问题

- 汇总阶段**有工具**，它会顺手改文件（这次它自己补齐了 README）。
  能力上合理，但语义上应显式：要么禁止写，要么在报告里标明"汇总阶段做了改动"。
- `node` 不在非登录 shell 的 PATH 里（nvm），子代理跑测试要靠绝对路径。
- 失败重试、依赖图、预算切分都还没有。


1. **依赖图**：现在只有一步并行 + 一步汇总，没有 DAG（A 的输出喂给 B）。
2. **仲裁/评审**：多个子代理可能互相矛盾，缺一个"评审者"角色。
3. **预算分配**：团队总预算没有按子任务切分，一个子代理可能吃掉大半。
4. **失败重试**：子代理失败只记日志，没有"换个说法重试"。
5. **真实模型验证**：目前只跑过脚本化模型（证明接线），还没用真模型跑过真任务。
