## 一句诚实的话

**301 个测试**（`bash tools/count_tests.sh` 实跑）——数字会变，以脚本输出为准；
门禁是 `bash tools/debug.sh` 那一串 `verify_*.sh`，CI 在 Linux 与 Windows 交叉编译上每推必跑。
这些是自动化能保证的部分。

以前这里的两条设计缺口（无 OS 沙箱、无观测式效果）已经补上了：Linux 有 fail closed 的
Landlock 写沙箱，shell/插件/MCP 执行前后有 `effect/observed` 实测改动。现在最该补的两条换成了：
**读侧没有沙箱**（`cat secrets/x` 拦不住，Phase 1-B），以及**网页端展示层不脱敏**。
这两条同样不是"多写点测试"能解决的——它们要先决定策略，再写代码。
