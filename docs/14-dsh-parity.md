# 对标 DSH：差距在哪

数据来源：`D:\deepseek_harness\resources\app.asar`（18,234 个文件，Electron 应用）。
用 `tools/dsh_probe.mjs` 读 asar 头部，按路径统计能力包。

## 一、DSH 真实的能力面（按包）

| 能力 | DSH 里的证据 | 我们的状态 |
|---|---|---|
| **MCP** | `dsh-mcp-client`、`dsh-mcp-resources`（客户端 + 资源两类） | 只有 tools，无 resources/schema |
| **子代理** | `dsh-client-ui-subagent`、`dsh-client-ui-settings-subagent`（有 UI 和设置页） | CLI 有，Web 没有；无并发/模型配置 |
| **会话** | `session` 相关路径 437 个 | 只有单会话 + journal，没列表/切换 |
| **技能** | `dsh-agent-preset/skills/*`（含插件开发模板、mcp-bundle 模板） | 有加载机制，无内置技能库 |
| **终端** | `node-pty`（真 PTY，ConPTY） | 管道 + 进程组（够用，但不是 PTY） |
| **搜索** | 内置 `rg.exe`（ripgrep 5.3MB） | 自己写的朴素匹配 |
| **文档预览** | `libreoffice-kit`（174MB）+ pdf/excel 预览包 | 无 |
| **语音** | `sherpa-onnx` + onnxruntime（离线 ASR） | 无 |
| **调试/检查器** | `dsh-experimental-inspector`（lighthouse worker） | 无 |
| **审计** | 未找到决策级日志/哈希链相关包 | **我们独有** ✅ |

**结论**：DSH 是"能力面很宽、工程很重"的桌面应用（Electron + 18k 文件 + 174MB 的
LibreOffice）；我们是"内核深、能力面窄"的单二进制。

## 二、"达到 DSH 水平"的准确含义

不是把上面每一条都抄一遍（文档预览、语音对核心价值贡献很小），而是**核心能力不输**：

| 维度 | DSH | 我们 | 差距 |
|---|---|---|---|
| 工具面 | 20+ 工具 + MCP 全量 | 7 个 + MCP tools | **明显落后** |
| 会话管理 | 多会话、列表、恢复 | 单会话 + 日志 | **明显落后** |
| 子代理 | UI 配置 + 并发 + 模型选择 | CLI 有，UI 无 | 落后 |
| 上下文压缩 | 有 | 有（锚点 + 摘要） | 平 |
| 权限/审批 | 有（permission 60 路径） | 有（效果集 + 精确审批） | **超过** |
| 审计/可复现 | 未见决策级日志 | 哈希链 + 血统 + 对账 | **领先** |
| 稳定性 | 桌面进程 + PTY | 崩溃对账 + 进程组 | 平/略优 |
| 分发 | 安装包 | 无安装包、无 CI | **落后** |

## 三、按"补齐到不输"排序

| # | 任务 | 为什么 | 成本 |
|---|---|---|---|
| 1 | **会话列表**（多会话、切换、删除、恢复） | DSH 的核心体验，我们完全没有 | 1d |
| 2 | **工具面补到 12+**：ripgrep 级搜索、patch、todo、job | 真实仓库里 7 个工具会卡 | 1d |
| 3 | **MCP 完整**：resources + inputSchema 透传 | 现在只有 tools，且参数是自由 JSON | 1d |
| 4 | **子代理 UI**：并发数、模型、预算 | 现在只能在命令行敲 | 0.5d |
| 5 | **安装包 + CI** | 没有分发就没有用户 | 0.5d |

前 3 项做完，"能用"这件事就和 DSH 打平；第 4 项决定好不好用；第 5 项决定有没有人用。

## 四、不该抄的

- **LibreOffice 预览（174MB）**：体积代价太大，需要时调外部命令即可；
- **离线语音**：不是核心场景；
- **Electron 外壳**：我们的 Web + 单二进制更轻，这是优势不是缺陷；
- **Inspector/lighthouse**：那是调试 DSH 自己的工具，不是用户功能。

## 五、我们真正的差异化（别在追赶中丢掉）

1. **决策级日志**：哈希链 + 效果集 + 审批留痕，可 `verify`、可 `audit --as` 重判；
2. **可复现科研链路**：实验包 + 输入血统 + 结论对账 + 多 seed 表；
3. **零运行时依赖**：单二进制 + 单 HTML，不需要 Node。

DSH 强在"什么都有"，我们强在"每一步都能解释"。追赶能力面的时候，
**这三点必须保持领先**，否则就变成了"又一个 DSH"。
