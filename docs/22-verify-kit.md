# 验证包：陌生人 30 分钟能亲手破坏的东西

来自外部评审的要求：**不要"请相信我"，要一套别人能自己跑、自己破坏、自己看结论的材料。**

```bash
bash tools/kit.sh        # 七个场景，一张表
```

输出：

```
场景                     预期         实际               结论
1 删改日志             退出 2       py=2 ui=2          BLOCKED
2 截短尾部             py=3 ui=0    py=3 ui=0          REPAIRED
3 并发强杀             链完整/可修复 py=0               REPAIRED
4 符号链接逃逸         拒绝读取     被拒               BLOCKED
5 shell 间接读密钥     GAP（已知）  读到明文            GAP
6 插件漏报效果         GAP（已知）  写了文件无记录       GAP
7 验收失败             退出 3       code=3             BLOCKED
```

**三种结论的语义必须分清**：

- `BLOCKED`：拦住了；
- `REPAIRED`：没拦住但能修复（截短、被杀）；
- `GAP`：**现在拦不住**，我们不假装。

## 独立校验器（不依赖 Rust 代码）

`tools/verify_journal.py` —— 纯 Python，只依赖下面这份格式说明，用来证明
"日志校验不需要相信我们的实现"。

```bash
python3 tools/verify_journal.py <journal.jsonl>
# 0 完好 / 2 链断或被改 / 3 尾部残缺（可修复）
```

### 日志格式（可独立实现）

每行一条记录：

```json
{"seq":N,"ts":毫秒,"kind":"...",<payload...>,"w":"写者","prev":"64hex","hash":"64hex"}
```

1. `hash = sha256( 本行**去掉末尾的 `,"hash":"..."` 之后**的全部字节 )`。
   注意是**按字节切掉尾字段**，不是"解析再序列化"——重新序列化会改变键序，
   永远校验不过。
2. 第一条的 `prev` 全 0；之后每条 `prev == 上一条的 hash`。

就这两条。任何语言 20 行能实现。

## 七个场景各自在证明什么

| 场景 | 做法 | 说明 |
|---|---|---|
| 1 删改日志 | 改正文一个字符 | 两套校验器都报错（py=2、ui=2） |
| 2 截短尾部 | 砍掉最后 40 字节 | 独立校验器报"残缺"，我们的 `verify` 修复后退出 0 |
| 3 并发强杀 | 3 个进程同写、`kill -9` | 链仍完整（flock + 补尾） |
| 4 符号链接逃逸 | 链接指向工作区外的文件 | 真实路径检查拒绝 |
| 5 shell 间接读密钥 | `cat secrets/providers.toml` | **读到了**——信任边界，见下面 |
| 6 插件漏报效果 | 声明 `effects: []` 但写文件 | **写了**——声明不是强制 |
| 7 合并后验收失败 | `--accept "test -f 不存在"` | 退出 3，不许宣布完成 |

## 必须承认的两个 GAP

1. **shell 是信任边界**：批准一条命令，等于批准它内部的一切读写与联网。
   效果集只记录"这条命令"，不记录命令内部做了什么。
2. **插件声明不是强制约束**：`effects: []` 只表示"它声称没有副作用"，
   内核不会验证。写文件照样发生，日志里也没有对应记录。

这两条在 `ui doctor` 输出里会直接打印，在 `docs/07-security.md` 里有对照表。
**解法分别是"观测式效果"和"OS 级沙箱"，都还没做。**
