# UI 设计

> 这份文档描述**已经在跑的东西**，不是愿景。凡是没实现的，都在最后"缺口"一节里点名。
> 诊断依据见 [01-diagnosis.md](01-diagnosis.md)。

## 0. 一句话

DSH 的问题不是功能少，是**行为不可解释**：305 个包各自正确，合起来没人能回答
"这一步模型看到什么、会被谁拦、花多少钱、崩了怎么办"。UI 把这些问题各自收敛成
一条**不可绕过的契约**，并用测试守住。

## 1. 三个立场

**不装插件系统。** 扩展点是数据（规则、剧本、外部进程协议），不是服务图。
cordis 那样的 DI 容器解决了"如何解耦"，代价是"行为由四十个策略交互涌现"。
原型阶段先要可预测性。

**不做依赖。** 零依赖不是洁癖，是三条现实约束：构建环境不可靠、供应链不该成为
安全边界、以及"内核小到一下午能读完"本身就是可审计性。代价是自己写 JSON、
SHA-256、glob；收益是 `cargo build` 永远不需要网络，且每个字节都可读。

**不做静默降级。** 压缩失败就带超预算历史继续跑、临时目录不可写就把文件写进工作区、
模型把 JSON 写坏就整步中止——这三种"优雅退化"是同一个错误的三种面孔：让状态
偏离报告。UI 的原则是**要么做对，要么报错**。

## 2. 七条契约

### 契约 1：一步一快照

`prompt.rs` 把提示词拆成带归属的段：`core`（内核）、`env`（环境）、`tools`、
`goal`、`history`。每段有 `owner`、`bytes`、`tokens`、`volatility`。
整段拼起来的文本取 SHA-256 前 16 位作为 `snapshotId`，写入日志。

- **可 diff**：两次快照的段级差异就是"这一步多了什么"。
- **可计价**：每段独立标价，谁膨胀了一眼可见。
- **可复现**：同输入同输出，测试直接断言 `a.id == b.id`。

`env` 段不是模板，是**探测 + 验证**：workspace 是否真的存在、临时目录是否真的可写、
shell 是什么方言。探测失败就写 `⚠`，而不是编一句"你的项目在 /app"。
（DSH 的运行时上下文曾把 `app.asar\dsh\` 当成源码目录发给模型，那个路径不是目录。）

### 契约 2：一调用一效果

工具不声明"权限模式"，而是按**这一次的参数**算出效果：

```
fs_write(path="src/a.rs")  → [fs.write /ws/src/a.rs]
shell(cmd="make test")     → [proc.exec make test]
```

`Tool { effects: fn(&Json, &Ctx) -> Vec<Effect> }`。这让"同一个工具，写工作区 vs 写
/etc" 变成两种不同的效果，而不是两种模式。

### 契约 3：一效果一决策

策略是数据：`[{effect, pattern, decision, note}]`，`**` 跨目录、`*` 不跨。
**最长字面前缀胜出**，所以"默认拒绝 + 精确放行"能自然表达。

`ui policy --effect fs.write --target /etc/passwd` 能离线解释任何一个决策。

批准请求带三样东西：工具名、**参数预览**、效果清单。批准 `a`（总是允许）会把该次
效果转成会话级规则——这是 DSH 缺的 `allow-always`。没有审批通道时**失败关闭**，
并回一个 `APPROVAL_UNAVAILABLE` 让模型知道原因，而不是让它反复撞墙。

### 契约 4：一预算一账户

分词是脚本感知的：ASCII ≈ 0.26 tok/字符，CJK ≈ 0.85，其余 ≈ 0.55。
DSH 用"4 字符 = 1 token"统一计价，对中文系统性低估 2–3 倍——这不是精度问题，
是预算失效。

四个维度：tokens / 工具调用数 / 墙钟 / 美元。`assert_room` 在花费**之前**检查，
所以不会出现"花掉一半才发现超了"。超支返回结构化错误给模型（`BUDGET`），
循环继续但该调用不执行——模型能看见墙，而不是被墙撞死。

提供方回报 usage 时，`reconcile_tokens` 用真实值替换估算值。

### 契约 5：一副作用一日志

追加式 JSONL，**每条事件一次 fsync**，每条记录带 `prev` 哈希形成链。

顺序是"先写日志，再执行"：`tool/request`（含决策）→ `tool/start` → 执行 →
`tool/end`。所以崩溃后的日志能回答"这个调用开始了、没结束"。

两种损坏被区别对待：

- **尾部撕裂**（崩溃撕掉半条记录）：截断到最后一条完整记录，并写一条 `journal/torn`
  记录这次修复。可用性优先。
- **中间篡改**：直接拒绝加载。完整性优先。

代价要说明白：尾部撕裂和后一条记录的篡改在字节上无法区分，所以"最后一条被改"
会被当成撕裂修掉。这是有意的取舍，写在测试名里（`repairs_a_torn_tail_and_says_so`）。

`resume` 对账：可重放的工具（读、搜）直接重跑；有副作用的（写、执行）**不猜**——
要么人工批准重放，要么记 `effect/unknown` 并列为需要人确认。DSH 的
"崩溃丢失已接受 prompt"在这条契约下变成一个具体的、可回答的问题。

### 契约 6：一委派一邮箱（最小实现）

设计：子代理是同一份日志里的另一条 turn 链，父子消息是日志行而不是内存队列。
这样才能跨进程、跨重启，也才谈得上"两个 harness 共享一个 store"。
当前实现停在"并行组 + 独立进程 + 独立 journal + 工作区副本 + `apply` 回写"：
父日志只记 `delegate/end`，不做父指针恢复与跨进程邮箱。够跑并行评审与隔离写入，
但还不是完整契约。

### 契约 7：一错误一修复

模型把工具参数写坏是常态，不是异常。三层处理：

1. **抢救**：剥代码围栏、补括号、截掉不完整尾巴，最多 24 次回退；
2. **修复回合**：仍未通过 → 记 `model/repair`，把错误原文回喂，最多 2 次；
3. **结构化失败**：仍失败 → 返回 `BAD_JSON` 作为工具结果，让模型下一步看见。

DSH 在这里是"打印 `tool input is invalid JSON`，中止整步"——一次真实的失败，
代价是整轮的上下文。

## 3. 数据流

```
输入 → build_snapshot ──► journal: prompt/snapshot
                        └─► budget.charge(tokens)
                             │
                             ▼
                        model.respond ──► journal: model/response
                             │                （参数坏了 → model/repair → 重试）
                             ▼
                   for each tool_call:
                        effects = tool.effects(args)
                        policy.decide(effects) ──► journal: tool/request
                             ├─ deny  → tool/end(DENIED)
                             ├─ ask   → hooks.on_approval ──► journal: approval/answered
                             └─ allow → budget.charge(calls)
                                        journal: tool/start  ← 先落盘
                                        tool.run(args)
                                        journal: tool/end
                             │
                             ▼
                    history += tool result → 下一步
```

## 4. 关键决策与替代方案

| 决策 | 替代方案 | 为什么不用 |
|---|---|---|
| 进程内单循环 | actor / 服务网格 | 原型阶段要的是可读的因果链 |
| 效果集 + 数据规则 | 权限模式（如 DSH 的 sandbox mode） | 模式无法表达"同一工具、不同目标、不同结论" |
| 先写日志再执行 | 执行后记录 + 重试 | 副作用不可撤销，事后记录等于承认会丢 |
| 快照分段 | 一个字符串 | 无归属就无法计价、无法 diff、无法归因 |
| 脚本感知分词 | 用 tiktoken 精确计数 | 无依赖约束下不可行；确定性比精度更重要，且接了真实模型后由 usage 校正 |
| 撕裂可修 / 中间必拒 | 一律拒绝 | 崩溃是常态，一条撕裂不该毁掉整段历史 |

**流式**：网页端已用（`on_delta` 只用于展示，最终文本仍以 `on_assistant` 与
`model/response` 落日志）；TUI 还没接。增量**不落盘**，否则会得到"日志里有一半
内容"的新问题。

## 5. Rust 核心 + TS 前端

内核（本仓库）拥有：日志、预算、策略、工具执行、循环。
TS 前端只做两件事：**渲染**与**输入**。分界是一条消息协议：

```jsonc
// 前端 → 内核
{ "type": "prompt", "text": "..." }
{ "type": "approval", "approvalId": "ap-…", "callId": "...", "verdict": "allow|always|deny" }
{ "type": "cancel" }

// 内核 → 前端
{ "type": "snapshot", "id": "...", "sections": [...], "tokens": 1234 }
{ "type": "assistant", "text": "..." }
{ "type": "tool", "callId": "...", "name": "...", "effects": [...], "decision": "ask" }
{ "type": "result", "callId": "...", "ok": true, "preview": "..." }
{ "type": "budget", "used": {...}, "limits": {...} }
{ "type": "turn-end", "reason": "done" }
```

这条协议让"先 TUI、后 GUI"不需要重写内核，也让 `ui` 可以同时是 CLI 与库。
`render.rs` 已经是纯函数（状态 → 行），换成全屏 TUI 或 Web 只是换渲染器。

**模型层**同理：`ExternalModel` 把快照用 stdin 喂给子进程、从 stdout 读一条 JSON。
将来要么写 HTTP+TLS 适配器，要么让 TS 侧做传输、Rust 侧做决策——两种都不改循环。

## 6. 上下文折叠

历史会一直涨。`compact.rs` 在**每一步**开始前检查，超阈值就折叠一次。

**保什么**：

1. 第一条用户消息（任务锚点）逐字保留；
2. 最近 N 条原文（默认 8）；
3. 被折叠的部分压成一条摘要，写进历史，**并且记进 journal**（`compact` 事件）。

摘要不调模型，只做确定性三件事：条数、工具调用统计（含失败次数）、被折叠的用户问题
（截断）。最后一条最有用——它保住了"用户要过什么"，是纯计数摘要与"能一直聊下去"
之间的分水岭。

**两条闸**：折叠必须真的变小，否则不动（否则会出现 `265 → 288` 的负收益）；
历史太短（≤ keep_recent+2）不折叠。

**为什么不用模型摘要**：多一次调用 = 多一个失败点、多一份成本、多一处不可复现。
确定性摘要先把"能一直聊"做出来；模型摘要留作可选策略，且必须失败时回落到确定性摘要，
而不是让上下文超预算继续跑。

**代价**：有损——保不住具体措辞、文件内容、推理链。实测模型会自己声明这一点
（"这条信息来自记录摘要，我无法回读原文逐字核对"）。

参数：`--compact-tokens N`（0 = 关闭，默认 12000）、`--keep-recent K`（默认 8）。

## 7. Skill 与工作流

两者都遵守同一个约束：**进入上下文的东西必须可计价，做过的事必须留痕。**

**Skill（渐进披露）**：只从 `skills/<名字>/SKILL.md` 发现；`.ui/` 是受保护目录，
不再作为隐式 skill 根。目录与文件都过统一隐私判定，真实路径必须仍位于 canonicalize
后的 `skills/` 内，软链不能把读取偷渡到工作区外或 `secrets/`。frontmatter 写
`name` / `description`。提示里只放目录（一行一个），模型用 `skill(name)` 工具才把正文拉进来。
正文作为 `skill-body` 段进入快照（owner=`skill`，可计价），并写一条 `skill/load` 事件
（谁、多少字节）。几十个 skill 也只占几行目录。

**工作流（文件驱动的多步）**：`{"name":..., "steps":[...]}`。每个元素要么是普通任务，
要么是并行组：

```json
{"name":"dual-review","steps":[
  {"prompt":"先读代码","skills":["code-review"],"gate":false},
  {"parallel":[
    {"prompt":"从安全角度评审","skills":["code-review"]},
    {"prompt":"从可用性角度评审","skills":["code-review"]}
  ]}
]}
```

- `skills`：这一步开始前**预加载**（正文进快照并写 `skill/load`，`source:"workflow"`）；
  并行子代理通过 `--skills` 参数继承同样的预加载。
- `parallel`：组内每个任务跑在**独立进程 + 独立 journal**（`.ui/agents/<id>/journal.jsonl`），
  父日志只记 `delegate/end {id, ok, summary, journal, workdir, changed}`——两个进程不会抢同一个文件，
  这就是契约 6「一次委派一条记录」的最小实现。
- **`--isolate`**：每个子代理再拿到一份**工作区副本**（`.ui/agents/<id>/ws`，跳过 `.ui/out/target/secrets`），
  只在副本里动文件；父工作区在运行期间保持干净。
- **改动清单来自文件系统比对**，不是子代理的自述：跑完逐文件与父工作区对比，得出 `changed`。
  实测一个子代理声称「SECURITY.md 已写入」，`changed` 是空的——它根本没写。断言比自述可信。
- `ui apply --id X [--yes]` / `ui apply --all`：默认只打印计划，加 `--yes` 才拷回工作区。
  **两道闸，宁可不合也不猜**：
  1. **冲突**：两个子代理改了同一文件且内容不同 → 跳过并退出码 3；
  2. **漂移**：复制那一刻给每个文件记了哈希（`.ui/agents/<id>/manifest.txt`），
     回写前重算父工作区里的哈希；文件被改过/删掉/新建过 → 跳过并退出码 4。
     `--force` 才允许覆盖。
  退出码：**0** 顺利、**3** 有冲突、**4** 有漂移（两者都有返回 3）、**5** 回写中途
  失败或上一次事务死在半路。`--json` 时 stdout 只有一行 JSON
  （`ok/exit/wouldWrite/written/restored/conflicts/drift/txn/unfinished/error`），
  人类可读信息走 stderr，脚本里可以直接 `ui apply --all --json | jq`。
- **`--yes` 是一个事务，不是一串 `copy`**（见 `run_apply_transaction`）：
  1. **先记日志再动手**——`apply/begin` 写不进日志就一个文件都不碰；
  2. **留底**——每个目标的原样先拷进 `.ui/apply/<txn>/before/`，「当时不存在」
     也记一笔（那种情况的回滚是删除）。备份在 `.ui` 里，模型读不到，
     它伪造不了「上一版长这样」；
  3. **状态落盘**——`.ui/apply/<txn>/manifest.json` 走
     `staged → applying → committed / rolled-back`；崩在写回途中时，下一条
     `ui apply` 认得出「上一半没写完」，退出码 5 停下来，`--force` 才肯继续；
  4. **写完就验**——内容哈希对不上源文件同样算失败，整批还原；
  5. **还原讲分寸**——事务内部失败是无条件还原（盘上只有我们自己的笔迹），
     事后 `ui apply --rollback [--txn ID] --yes` 只还原「仍然是事务当初写进去
     的那份」，用户在 apply 之后自己改过的文件不碰、留底也不扔（退出码 4）。
     退干净了留底才删；`--rollback` 不带 `--yes` 是计划模式。
     每一步都在日志里：`apply/begin` / `apply/committed` / `apply/rolled-back`。
- **取消传播**：父进程给每个子进程一根 stdin 管道并一直握着；父进程一死（含 SIGKILL），
  管道关闭，子进程读到 EOF → `cancel_hard()` → 停。这里不用信号（std 没有），
  但要区分「硬取消」与「普通取消」：`turn` 开头的 reset 只能清后者，否则父亡会被下一轮抹掉。
  同时 `shell` 工具会轮询取消令牌，长命令也能被打断。
- **复制成本**：大文件（≥1MB）先试 `cp --reflink=auto`（btrfs/xfs 上是 O(1)），
  ext4 会退化成普通复制；`target`/`node_modules`/`.ui`/`secrets` 一律不复制。
  实测 21MB 工作区复制 + 跑一轮 ≈ 0.07s（页面缓存友好时）。
- 子代理的答案通过 `--result-file` 回传，而不是从 stdout 里猜（stdout 混着日志）。
- 组结果会作为一条 `note` 进父历史，后续步骤能接着用。
- `gate` 为真的步骤先要人批准；未批准 → `workflow/end {reason:"gated"}` 并返回非零。
- 任一步 `reason != done` → 中止并如实记录停在第几步。

## 8. 成本：让长输出离开上下文

每个工具结果都会在后续**每一步**被重发一次，所以"读了一次 500 行文件"会变成长久的上下文税。
现在超过 `tool_chars`（默认 **2000**；`0` 只作为显式关闭，不再是默认）的输出会：

1. 全量落盘到 `.ui/tool-output/<toolSeq>-<writer>-<日志seq>-<tool>.txt`——名字里必须带
   writer 和日志序号：`toolSeq` 每个 run 归零，只用它会让后一个 run 覆盖前一个 run
   的留底，上一轮历史里那句「完整内容在 …」就指向了别人的输出；
2. 上下文里只留**首 2/3 + 尾 1/3 + 一行指针**；
3. 写一条 `tool/trim {totalChars, keptChars, file}` 日志；
4. 落盘那一份不是永久物：默认 7 天 / 200 个 / 256 MiB，超了从最旧的删，run 边界自动清一次（`ui spill` 看，`ui spill clean` 手动）。

模型需要细节时可以 `fs_read` 那个文件——**按需展开，而不是常驻**。`.ui` 整体是安全边界
（`protected::PROTECTED_DIRS`：日志、会话、配置里有完整提示词和工具结果），
`.ui/tool-output/` 是里面**唯一的读取例外**，且不豁免写：往截断缓存里写文件等于给
下一轮的模型喂伪造的「完整内容」。

### 为什么落盘要拆成两个目录

把正文留在盘上（哪怕在 `.ui` 里）之后，隐私就变成两个问题：**这一份谁能读到**，
以及**它会在盘上待多久**。原来只有一个目录，两个问题都没法答：
被隐私清单命中的输出既要"不给模型看"，又确实要落盘给人复盘，于是只能挤在同一个
读取例外里。

现在是两个：`.ui/tool-output/` 是模型可读的截断缓存（唯一的读取例外），
`.ui/tool-private/` 是按清单扣留的原文，**刻意不在任何读取例外里**。
这个不对称是第二档的全部意义：日志里那句「全文在 …」本身就是给模型看的提示词，
它照着 `fs_read` 一下，扣留就白做了。反过来，被截断的普通输出也不能"顺便"落进
扣留目录——那是给人看的，模型按需展开会读不到东西。

保留期按**两目录合并的一份预算**算（`spill::plan_all`）。这件事一开始就写错过：
拆目录时在注释里说"上限合计算"，代码仍是逐目录各调一次 `plan`——那就是每个目录
各领一份完整预算，200 个变成 400 个。现在的回归测试叫
`the_budget_is_shared_across_both_directories`，专门盯这一条。

完整的两档语义、事件名与开关清单见 [docs/07-security.md](07-security.md)「隐私：两档处理 + 生命周期」。

**实测（A/B，同一注入、同一任务）**：

| 组 | `--tool-chars` | tokens | 步 | 工具调用 | 耗时 | 测试 |
|---|---|---|---|---|---|---|
| A | 0（不截断） | **72,791** | 12 | 16 | 127s | 绿 |
| B | 2000 | **78,270** | 14 | 19 | 116s | 绿 |

开截断反而**多花 7.5%**：截断逼模型重读，多出来的探索比省下的字符更贵。
但“更便宜”不等于“可以默认无界”：默认 0 会让一次 8MiB 输出原样常驻 history。
所以现在默认 2000（与内核默认一致），需要完整上下文时显式 `--tool-chars 0`。
这是一次安全性优先于成本的取舍，不是对上面实测的否定。

## 9. 多进程共享一份日志

并行子代理要真正共享工作区，日志就得允许多个 writer。三件事缺一不可：

1. **写前独占锁**（Unix `flock`，进程崩溃内核自动释放；其他平台用锁文件 + 60s 过期兜底）；
2. **补读**：拿到锁后先把「我上次读到位置之后」别人写的记录读进来、对齐 `seq`/`prev`，
   然后才写自己这条——否则两个 writer 各持旧 seq，链必断；
3. **原子创建**：`open` 不能写成 `if !exists { write("") }`——判断和写之间会被插进来，
   后者把前者刚写的记录截断（真实踩过：三进程并发丢两条）。

另外每条事件带 `w`（writer id）：交织的 `turn/start`/`turn/end` 靠它归属，
否则 `verify` 会把 A 的结束算到 B 头上，永远报「有未完成 turn」。

## 10. 五个"静默失败"的教训

前两条属于"把失败当成功"，后三条属于"做了、却没留下能读懂的痕迹"：

1. **空回复被当成完成**：模型返回空内容，循环直接 `done`。现在空回复记 `model/empty`
   并要求续写，连续两次才以 `empty_reply` 如实结束。
2. **散文被当成最终答案**：模型没按 JSON 协议输出，适配器把原文当 content，任务看起来
   完成了其实没做。现在适配器返回 `protocolError`，内核按"参数坏掉"同等对待：记
   `model/repair` 并要求重写，最多两次。

3. **撤掉的任务与写回的改动只活在终端里**：排队中被撤掉的任务原来只往 SSE 推一条
   `task-cancelled`，日志里查不到——事后翻账只能看到"这条没跑"，分不清是撤了、丢了、
   还是压根没提交。`ui apply` 的写回与回滚同样只有人眼可读的输出。更糟的是查看器按
   `prompt/snapshot` 分组，**不属于任何一轮的事件被整段丢掉**：导出给别人看的轨迹里，
   合并和回滚根本没发生过。现在它们各自有账（`turn/skipped`、
   `apply/begin|committed|rolled-back|abandoned`），`ui replay` 有一行人话，
   查看器多一张「旁路事件」卡专门收这些步骤之外的操作。

4. **"没人回答"被记成"有人拒绝"**：`approval/answered` 原来只有 `verdict`。于是 300 秒
   超时、被停止打断、审批卡失效、压根没接通道、`--yes` 代批，在账本里全和人手打一个
   `n` 一模一样——复盘时会得出"这个人否决过这些操作"，而事实是没人答过。现在回执多一个
   `via`（`timeout`/`cancelled`/`stale`/`no-channel`/`unknown-word`/`auto`/`no-input`），
   **人明确表态时它不存在**；`ui replay` 把那行写成"（300 秒没人答，按拒绝）"这样的人话。
   口子没有因此变宽：认不出来的词仍旧按拒绝，只是不再静默。同理，CLI 读不到 stdin 记
   `no-input`、读到听不懂的词记 `unknown-word`，两者不再混为一谈。
5. **`tool/output` 那行是空白的**：模型这一步实际看到多少字、有没有被截断落盘，正是
   "上下文税"的第一问，而账本里它渲染成一行空白。现在 `ui replay` 印
   `fs_read · 模型看到 1342 字（已截断，全量落盘）`。

共同点：**任何"没做完"都必须以非 `done` 的原因结束，任何"动过工作区"或"替人做了决定"
都必须落到日志里并且读得懂**——否则日志和界面在说谎。

## 11. 路线图

1. **v0.2 委派与邮箱**（契约 6）：已做并行组 + 独立日志 + 隔离副本 + `apply`；
   还差父指针恢复与跨进程邮箱。
2. **v0.3 全屏 TUI**：已完成（对话、审批、滚动、命令、宽屏「当前步」右栏）。
3. **v0.4 执行侧沙箱**：已完成**读侧最小根与写侧**——Linux 用 user/mount
   namespace + chroot 只暴露系统运行时、工作区和显式白名单，隐私路径用空目录/文件
   遮住；Landlock 把写限制在工作区与 `/tmp`，`UI_SANDBOX_NET=1` 可禁 TCP。
   namespace、挂载或 Landlock 不可用时**直接失败**（fail closed，不静默降级）。
   Phase 1-B 的 shell 命令串 `read.private`（默认 ask）与 `provesRead:false`
   observed 继续负责审批与留痕；它们不冒充实际读取证明。Windows 仍无对等文件视图。
4. **v0.5 上下文治理**：已完成确定性折叠；下一步模型摘要 + 分层记忆。
5. **v0.6 真实模型**：已完成 DeepSeek 子进程适配器与网页端流式；
   下一步 TUI 流式与更细的 usage 对账。

## 12. 缺口（诚实清单）

- 委派只有最小实现（契约 6）：没有父指针恢复与跨进程邮箱。
- TUI 还没有逐字流式（`on_delta` 只接了网页端），也还没有每行时间戳。
- `shell` 在 Linux 上有 OS 级**读侧最小根 + 写侧沙箱**（fail closed）；Windows 只有
  Job Object，没有文件读写限制。Linux 隐私路径遮罩不覆盖硬链接同 inode 别名；命令串
  命中隐私路径时仍追加 `read.private` 并触发审批，observed 明确不证明实际读取。
- 落账前的脱敏门是**模式匹配**，不是 DLP：没有密钥形状的机密会照原样进日志。
- 网页端不脱敏：推给页面的是未脱敏的第一行，`/api/tool/<id>` 给全量原文。
- MCP 只接了 tools：无 `inputSchema` 透传、无 resources/prompts、无超时重连。
- 日志本体（`journal.jsonl`）无轮转/删除；`.ui/tool-*` 两个落盘目录有保留期与自动清，
  但那是**脚印**的清理，不是审计记录的清理——断掉的指针仍要在 `ui doctor` 里说清楚。
  多写者靠 `flock` + 补读，不是完整的存储层。
- Windows 原生跑未验证（TUI 依赖 POSIX `stty`，argv 非 ASCII 经 WSL 桥可能乱码，
  故提供 `--task-file`）。
