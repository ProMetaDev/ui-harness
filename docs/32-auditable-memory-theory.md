# 32 · 可审计的记忆与知识：一份理论草稿

> 状态：草稿（v1.0.1 之后写）。**引用部分待补**：本文件的机制性结论我们自己在 v1.0.1 上验证过；
> 与既有工作的对照由调研补齐（见 §6 的标注规则）。
>
> 一句话主张：
> **agent 的记忆与知识要可信，靠的不是更强的检索，而是让"这条信息从哪来、为什么被用、什么时候失效"
> 三件事都变成可判定的。** 可判定性有代价——它排除了一整类"看起来更聪明"的做法。
>
> 术语说明：本文所说的"**三个系统边界条件**"（§2.4）**不是** FLP/CAP 那种形式化不可能定理，
> 而是本系统（观测式效果）与单机密码学链（哈希链）在既定架构下的边界。

---

## 1. 问题：三个不可信

### 1.1 来源不明

模型的记忆里有一条"这个仓库用 `make test` 跑测试"。它是谁写的？从哪次运行里总结的？
对应哪个 commit？如果仓库换成 `cargo test` 了，这条还成立吗？

主流做法（把摘要写进向量库）回答不了这些，因为**写入时就丢掉了来源**：
摘要是一段自然语言，与产生它的那次运行之间没有可检查的链接。

### 1.2 注入不可复现

同一个任务跑两次，注入的记忆可能不同。原因通常不是模型，而是**检索**：
近似最近邻（ANN）索引是近似的、可变的、异步更新的；同一查询在不同时刻可能返回不同集合。

于是"这次为什么这么答"无法重放——不是模型随机，而是**上下文本身就不可复现**。

### 1.3 过期不可检出

知识写下来的那一刻是正确的，之后源码变了。没有任何机制会让这条知识"自己知道自己过期了"。
结果是最坏的一种失败：**自信地引用过时的规范**，而且日志里看不出异常。

## 2. 形式化

### 2.1 事件与链

一次运行产生事件序列 `L = e₁ … eₙ`。每个事件：

```
eᵢ = (seq=i, kind, payload, prev=hᵢ₋₁, hash=hᵢ)
hᵢ = SHA256( eᵢ 去掉 hash 字段后的字节 )
h₀ = GENESIS
```

`L` 就是"实际发生了什么"的唯一记录。本文件后面所有"可审计"的说法，都以此为基准。

### 2.1.5 我们不是"透明日志"（这一节标明证据等级）

透明日志（如证书透明 CT，[RFC 6962](https://www.rfc-editor.org/rfc/rfc6962)）用的不是单链，
而是 **Merkle 树 + 签名的树头（STH）+ 监视者与 gossip**。这套机制解决的是单链解决不了的问题：

| 能力 | 单链（我们） | Merkle 树 + 签名 + 见证 |
|---|---|---|
| 检测中部篡改 | ✅ | ✅ |
| 检测尾部截断 | ❌ | ✅（对着 STH 比） |
| 防止"对不同人展示不同版本"（equivocation） | ❌ | ✅（gossip / 监视者） |
| 需要第三方在线 | 不需要 | 需要 |

> 证据等级：**B**。上述机制描述来自标准与公开资料，我**没有**逐条核对 RFC 原文措辞；
> 因此这里只用来划定"我们缺什么"，不作为引用依据。

结论：我们是**本地审计日志**，不是透明日志。前者服务"事后说得清"，后者服务"对互不信任的第三方证明"。
把两者混为一谈，是"可审计"这个词最常见的滥用。

---

### 2.2 断言与支撑集

**断言**（claim）：一条关于系统或代码的陈述 `c`，带两个附属结构：

- **作用域** `scope(c)`：一组路径模式（如 `src/pay/**`）；
- **支撑** `sup(c)`：要么是码源指纹 `sha(scope(c))`，要么是日志位置 `{(journal, seq)}`。

**记忆条目**是断言 + 元数据（写者、时间、有效期、置信度）。
**知识卡**是断言 + 码源指纹（我们的 `source_sha`）。

关键设计选择：**支撑必须是可重算的**。`source_sha` 的定义是
"对 `scope` 命中的文件按路径排序，逐行喂 `路径\n sha256(内容)\n`，再取 sha256"——
它是纯函数，任何人都能独立重算，不需要信我们的实现。

### 2.3 六个性质（都可判定）

| 性质 | 定义 | 判定方法 | 我们怎么做的 |
|---|---|---|---|
| **P1 可溯源** | 每条 live 断言都能追到 `sup(c)`，且链接可检查 | 读日志即得；`memory check` 校验引用完整性 | `knowledge/emit` 带 `source_sha` + `generated_by_seq`；`memory/write` 带 `sourceKind`/`sourceSeq` |
| **P2 注入可复现** | 给定 `L`，重放得到**同一组**被注入的条目与 token 数 | `ui replay` 重建；不看模型输出 | `knowledge/use`、`memory/used` 写入 id / reason / tokens |
| **P3 可证伪** | 存在一个可执行过程，能判定断言已失效 | 重算 `source_sha` ≠ 卡上值 → STALE | `ui knowledge check`（STALE 退 2）；`--strict` 把"未绑定"也算红 |
| **P4 可撤回** | 撤回不删除历史；live 集合是日志的纯函数 | `live(L)` 可由 `L` 重算 | `memory/forget` 写墓碑；`list` 默认只列 live |
| **P5 冲突可检** | 两条 live 断言在同一 `(scope,key)` 上内容不同 → 可发现 | 键扫描 | P1 只做硬键冲突（同键不同 id → 退 1） |
| **P6 检索有界确定** | 检索是 `(query, live 集合, 预算) → 条目集` 的**纯函数** | 同输入两次跑，集合应相同 | BM25 + 路径/关键词加成，无 ANN、无隐状态 |

这六条里，**P2 与 P6 是一对**：没有 P6，P2 就不成立。这也是为什么我们拒绝 ANN——
不是因为它效果差，而是因为它**把可复现性卖掉了**。

### 2.4 三个系统边界条件

这三条是我们必须承认的边界，写在文档里比藏在实现里诚实。

#### 结论 A：观测是下界，不是等价

信任边界（shell / 插件 / MCP）的"实际改动"靠观测得到。观测函数 `O(行为)` 返回
**被我们看见的**改动集合。必然有：

```
O(行为) ⊆ 实际改动
```

因为我们靠事件队列或元数据扫描采样，总有看不见的时刻（进程在两次采样之间改了又改回来、
事件队列溢出、文件系统不支持 inotify）。

**推论**：日志里没有 `effect/observed` **不等于**"什么都没发生"。任何"shell 不可能写出 X"的断言，
都不能靠观测来证明。这就是为什么 `docs/22` 的攻击表里"shell 间接读密钥"永远是 GAP——
不是我们偷懒，是观测这类机制在原理上够不着。

#### 结论 B：上下文可复现 ≠ 输出可复现

我们能做到的是：给定 `L`，重建**模型当时看到的上下文**（同一条提示词、同一组注入条目）。
做不到的是：重建模型的下一个 token。

所以"可复现"这个词必须限定对象：

> **我们复现的是上下文与决策依据，不是生成结果。**

这条限制不是缺陷，它是 LLM 系统的物理事实；把它写清楚，才能让"审计"有意义——
审计问的是"当时依据什么"，不是"当时为什么选这个词"。

---

#### 结论 C：纯哈希链检测不了"干净截断"

我们此前一律说"日志可校验"。准确的表述要更窄一层。

**实验**（`tools/verify_truncation_gap.sh`）：把日志最后 3 行**整行**删掉（不是崩溃留下的半行），再校验：

```
原始事件数: 19
截断后事件数: 16
verify 退出码: 0
ok    哈希链完整
事件  16
序号  1..16
```

`verify` 说"完整"。因为它检查的是：从 GENESIS 开始、每行 `prev` 接得上、`seq` 连续。
**删掉尾部剩下的仍是一条合法前缀**，所以通不过检查的反而是"没问题"。

这里必须区分**两种攻击者**，否则就会过度承诺：

| 攻击者 | 只改字节、不重算哈希 | 改完从改动点往后**重算哈希** |
|---|---|---|
| 中部修改 | 被发现（`prev`/`hash` 断了） | **发现不了**——他会得到另一条自洽的链 |
| 尾部截断 | 半行撕裂会被 `verify` 修复并标记 | **发现不了**——剩下的本来就是合法前缀 |

所以单机、无签名、无外部锚定时，能声称的最强性质只有一条：

> **日志是自洽的，不是真实的。** 校验能证明"这份日志没有被随手改过"，
> 不能证明"这份日志就是当时发生的那一份"。

要跨过这条线，必须有**日志之外的对账点**。这也是为什么 §2.4 的补救表把"外部锚定"
排在第一——它是唯一在零依赖、单机前提下还能拿到真实性的手段。

这与结论 A 是同一类错误：把"我们看见的"当成"实际发生的"。

#### 补救的层次（从弱到强）

| 手段 | 能挡什么 | 代价 | 我们的状态 |
|---|---|---|---|
| 校验和（现在） | 中部篡改、崩溃撕裂 | 无 | ✅ 已做 |
| **外部锚定**：把"头部哈希 + 事件数"写到日志之外（实验包 claim、release 产物、CI 输出） | 截断到锚点之前 | 低 | ⚠️ 可做，未做（见待办 V1） |
| 定期签名（对称/非对称密钥） | 截断 + 伪造链 | 引入密钥管理 | ❌ 零依赖下不做 |
| 透明日志式：Merkle 树 + monitor + gossip | 截断、分叉、回滚 | 要有第三方见证 | ❌ 单机不适用 |

我们选"外部锚定"，因为它不需要密钥、不需要第三方：只要**导出**或**发布**时把头部哈希写进
一份不带在日志文件里的记录（实验包的 `claims.json`、release 的校验和），事后就能对账。
后续计划落在待办 V1（`ui verify --expect-head` + 打包时记录）。

## 3. 这些性质换来了什么

### 3.1 三类问题从"说不出"变成"能说出"

| 问题 | 没有 P1–P6 | 有 P1–P6 |
|---|---|---|
| 这次为什么这么改？ | "模型觉得应该这样" | `memory/used m-3f9a1c reason=keyword-match:门禁` → 那条记忆是第 41 轮写的 → 它引用的源码已变（STALE） |
| 这条规范还成立吗？ | 没人知道 | `ui knowledge check` → 2 |
| 上次的结论能重放吗？ | 只能看输出 | 注入集合与 token 数可精确重建 |

### 3.2 代价

1. **写入变贵**：写一条记忆要能说清来源，所以 P1 只允许**人**写（`ui remember`）。
   让模型自己写记忆最容易污染审计——这是有意的限制，不是没做完。
2. **检索变笨**：确定性命中（路径 / 关键词 / BM25）在语义相似度上不如向量检索。
   我们接受这个损失，换取可复现。
3. **需要维护"支撑"**：卡片要绑定 `source_sha`，源码一动就 STALE。这是**负担**，
   但也是它唯一能"知道自己过期"的方式。

## 3.5 上下文经济学：为什么"记下分配"比"分配得最优"更重要

检索本质是一个约束优化：

```
max   Σᵢ u(cᵢ | query)
s.t.  Σᵢ tokens(cᵢ) ≤ B
```

`u` 是"这条断言对当前任务的有用程度"。问题是 **`u` 不可观测**——
要测它，得知道"注入了这条"与"没注入这条"两次运行的结果差异，而模型输出不可复现（结论 B）。

于是所有实际系统都在用**代理指标**：BM25 分数、向量相似度、命中次数、路径匹配。
代理指标与 `u` 的相关性，在特定任务上可能很高，但**没有一般性保证**。

这里有个容易被忽略的推论：

> 既然无法证明分配最优，那么"可审计"的最小要求就退一步——
> **把分配记下来**：这次注入了哪些条目、各自的 token 数、命中原因。

这恰好是 `knowledge/use` 与 `memory/used` 在做的事。它不声称"选得对"，
只声称"选了什么、为什么"。**可问责性替代了最优性**。

这也解释了为什么 `score` 字段默认是 `null`：确定性命中（路径/关键词）不产生相似度，
硬填一个数字反而是在编造一个不存在的度量。宁可空着。

## 3.6 冲突的三种语义（决定 P5 能走多远）

| 层 | 定义 | 能否判定 | 我们的状态 |
|---|---|---|---|
| **L1 硬键冲突** | 同一 `(scope,key)` 上有两条 live 断言，内容不同 | 能，纯字符串比较 | ✅ P1 已做（写第二条退 1） |
| **L2 语义矛盾** | 不同 key 的两条断言互相否定（"用 make" vs "用 cargo"） | **不能**，需要语义等价判定 | ❌ 未做，且我怀疑做不对 |
| **L3 时间竞争** | 两条都曾经正确，新的取代旧的 | 部分能：用 `expiresAt` + 写入时间排序 | ⚠️ 只有过期，没有"取代"关系 |

L2 是记忆系统最容易翻车的地方，也是最容易被吹的地方（"AI 帮你发现矛盾"）。
诚实的做法是：**承认 L2 不可判定**，只做 L1 + L3，并在文档里写清。
若将来要做 L2，唯一可接受的形态是"**提示人来看**"，而不是"自动合并"——
因为自动合并的判据同样不可证伪。

## 4. 可检验的预言

理论如果不能被证伪，就只是措辞。以下三条可以用我们自己的 `lab` 跑出来：

| # | 预言 | 怎么测 | 反例长什么样 |
|---|---|---|---|
| H1 | 开启 `knowledge check` 门禁后，"注入了 STALE 卡片"的运行次数降到 0 | 同一批任务跑 with/without 门禁，数 journal 里"被注入的卡片是否 STALE" | 出现一次注入 STALE 卡而门禁没拦 → 门禁有洞 |
| H2 | 确定性检索在相同输入下注入集合完全一致 | 同 workspace 跑 20 次，比较 `memory/used` 的 id 序列 | 任意一次集合不同 → 检索有隐状态 |
| H3 | 记忆注入对任务成功率的提升**可测但不显著**（在我们的小样本上） | lab A/B：with/without memory，各 20 次，看成功率与 token | 若声称"显著提升"却拿不出可复现的 A/B → 那是话术 |

H3 是我故意写的：**我们不应该假装记忆一定让任务更好**。它首先让任务**更可解释**；
效果要单独测，而且可能测不出来。这一点和 Qoder 那类"越用越聪明"的宣称形成对照
（见 `docs/29`：它们的数字没有一个能多源确认）。

## 5.5 已做的实验（不是设想）

理论里最有价值的两条，我们当场跑了实验，脚本留在仓库：

### E1：确定性检索（对应 §4 的 H2）

```bash
bash tools/verify_h2_determinism.sh
```

同一 workspace、同一任务、同一批记忆，连跑 20 次，比较 `memory/used` 的 id 序列：

```
1  m-78f5580faabd,m-947662e7959d
2  m-78f5580faabd,m-947662e7959d
…（20 行完全相同）
20 m-78f5580faabd,m-947662e7959d
不同序列数: 1
```

**结论**：P6 成立。另外那条无关的记忆（"周三发布窗口在下午"）**没有被注入**——
说明检索不是"把所有记忆塞进去"，而确实在按相关度选。

这个实验的价值在于：它把"我们不用向量检索"从**偏好**变成了**可检验的性质**。
换成 ANN 索引，这个实验就不该保证通过了。

### E4：重算哈希即可伪造（结论 C 的强化版）

```bash
python3 tools/demo_rewrite_chain.py <journal.jsonl> ui
```

脚本用 **Python 独立实现**链规则（不依赖我们的 Rust 代码），改掉第 10 条事件，
然后把后面 5 条的 `prev`/`hash` 全部重算：

```
已修改第 10 条并重算其后 5 条的哈希
verify 退出码: 0
ok    哈希链完整
```

**结论**：`verify` 通过。所以"哈希链"能证明的是**自洽**，不是**真实**。
任何能写这个文件的人，都能造出一份自洽的假日志。

（写这个脚本时我连续错了两次：先忘了去掉旧的 `hash` 字段，又忘了哈希前缀要补回 `}`。
两次都被 `verify` 抓出来了——这本身说明校验对"随手改"是有效的，只是挡不住"认真重算"。）

---

### E3：截断不可检测（对应 §2.4 结论 C）

```bash
bash tools/verify_truncation_gap.sh
```

把日志最后 3 条**整行**删掉，再校验：

```
原始事件数: 19
截断后事件数: 16
verify 退出码: 0
ok    哈希链完整
```

**结论**：删掉尾巴后剩下的仍是合法前缀，校验通过。
所以"可校验"的正确含义是**前缀一致**，不是**完整**。
要检测截断，必须有日志之外的对账点（见 §2.4 的补救表与待办 V1）。

---

### E2：观测是下界（对应 §2.4 结论 A）

```bash
bash tools/verify_observation_lower_bound.sh
```

让 shell 往**工作区外**写一个文件：

```
工作区外的文件是否真的被写了: 是
日志里 effect/observed 事件数: 0
```

**结论**：确实发生了写入，日志里没有任何记录。所以唯一站得住的表述是
「观测 ⊆ 实际」，而**不是**「没记录 = 没发生」。

这也解释了为什么"shell 间接读密钥"是原理性 GAP：观测机制的范围是工作区，
而越界行为在范围之外。

## 6. 与既有工作的关系

标注规则与 `docs/29` 一致：**A 多源确认 / B 单一来源 / C 只有论文自述 / D 查不到**。
本节的 arXiv 编号与引语均经原文核对（见文末参考）。

### 6.1 记忆系统：优化的是效果，不是可审计性

| 工作 | 机制一句话 | 最接近我们哪条性质 | 缺什么 |
|---|---|---|---|
| [MemGPT](https://arxiv.org/abs/2310.08560) (2023) | 主上下文 / 外部存储分层，由 LLM 自己发 function call 搬数据 | P4（编辑是显式调用，可记录） | 不记录"为什么检索到这一条" |
| [Generative Agents](https://arxiv.org/abs/2304.03442) (2023) | 记忆流 + 周期反思 + recency/importance/relevance 三合一打分 | P6 的反面（relevance 是 cosine，非确定） | 无逐跳因果记录，不可回放 |
| [Reflexion](https://arxiv.org/abs/2303.11366) (2023) | 失败后写反思文本，下轮试验注入 | — | 反思不校验真伪，无引用链 |
| [Voyager](https://arxiv.org/abs/2305.16291) (2023) | 可执行代码技能库，**执行通过才入库** | **P3（可证伪）**：技能是程序，能跑 | 不记录"为何选这个技能" |
| [A-MEM](https://arxiv.org/abs/2502.12110) (2025) | Zettelkasten 式笔记 + 建链 + **反向改写旧笔记** | P5 的反面（演化覆盖旧属性） | 覆盖无版本 → 撤回不可行 |
| [MemoryBank](https://arxiv.org/abs/2305.10250) (2023) | 按艾宾浩斯遗忘曲线衰减/强化 | P4 的近似（会遗忘） | 无归因、无对照，C 级证据 |
| [Mem0](https://arxiv.org/abs/2504.19413) (2025) | LLM 抽取 → 整合去重 → 检索 | — | 无 provenance，更新即覆盖 |
| [Zep/Graphiti](https://arxiv.org/abs/2501.13956) (2025) | 时序知识图；矛盾时给旧边置 `t_invalid` | **P4（唯一有撤回原语）+ P1 的近似**（episode→fact 回指） | 矛盾检测由 LLM 判定，不可复现；论文自承回指"not directly examined" |

### 6.2 三条对我们有利的文献事实

**第一，「记忆带来提升」这个核心断言经常被最朴素的基线推翻。**

- MemGPT 自报 DMR 93.4%，而**同一基准下 full-context 是 94.4%**（B/A）。
- Mem0 自报"比 OpenAI 相对提升 26%"，但 Zep 复现得 66.88%（Zep 自己 75.14%），
  且 **Mem0 论文自己的表里 full-context ≈73%，已高于 Mem0**（A，双方公开互撕）。
- Zep 自己的表里，knowledge-update 这一类是 **-3.36%**（B）。

推论：如果"把所有东西塞进上下文"就够好，那么记忆系统的价值必须建立在
**成本**（token/延迟）与**可解释性**上，而不是"效果更强"。这和 §3.5 的结论一致：
我们能诚实主张的是"更可解释"，不是"更聪明"。

**第二，溯源从一开始就是未解项。**

RAG 原文（[2005.11401](https://arxiv.org/abs/2005.11401)）自己把
"providing provenance for their decisions"列为开放问题。五年后，
2026 年的综述（[2606.04990](https://arxiv.org/abs/2606.04990)）普查结论是：
"no benchmark in our catalog that evaluates the complete provenance chain"、
"little reporting of tamper-evident or attested traces"。

**第三，基准本身有洞。**

- LoCoMo（[2402.17753](https://arxiv.org/abs/2402.17753)）已知 category 5 无 ground truth、说话人错标（Zep 指出，A/B）。
- MemoryAgentBench 的再分析（[2610.09193](https://arxiv.org/abs/2610.09193)）用零学习 resolver 拿到 80.25%，
  并指出 **67 道题的 gold 不可达** → 聚合分数不可读（B）。

这解释了为什么 `docs/29` 里 Qoder 的那三个数字无法采信：不是我们苛刻，
而是这个领域的"基准—复现"链条整体脆弱。

### 6.3 我们的位置（准确表述）

调研的结论是：**没有任何一篇把「记忆条目 → 被检索 → 进入上下文 → 影响该步动作」
做成逐跳可重放的记录。** 最接近的两处各补一半：Zep 有回指但没有逐跳重放，
Voyager 有执行级验证但不记录检索归因。

所以我们能声称的是（严格版）：

> 在**上下文这一层**（注入了哪些条目、为什么命中、各占多少 token），
> 我们做到了逐跳可重放与可校验；在**模型这一层**（为什么选这个词），我们不声称（结论 B）。

这个表述比"可审计的 AI"窄得多，但它是真的。

### 6.4 一条需要注意的反对意见

有文献把"记忆"做成了**可执行**的形式（Voyager 的技能库）：能跑通才入库。
这是比我们的 `source_sha` 更强的可证伪性——哈希只能证明"源码没变"，
不能证明"这条知识是对的"。

诚实的回应：**我们的断言比它弱**。知识卡是自然语言建议，不是程序，
所以只能绑定来源、不能绑定正确性。若将来要做强断言，方向是"把可执行的部分变成可执行"
（例如卡片里带一条能跑的命令），而不是给自然语言打分。

## 7. 开放问题

1. **跨会话的支撑失效**：卡片绑定的是"当时的源码"。如果源码整体重构（文件改名），
   支撑会永久失效，卡片变砖。需要"重新绑定"的语义（我们只有 `bind`，没有"迁移"）。
2. **冲突的语义**：硬键冲突能检出，但"两条不同 key 的记忆互相矛盾"检测不了。
   需要语义层面的矛盾判定，而那需要模型——又回到不可判定。
3. **观测的下界能否抬高**：结论 A 说观测只能给下界。有没有办法给**上界**？
   （例如：把 shell 放进可记录的系统调用沙箱，就能从"采样"变成"全量记录"。代价是平台绑定。）
4. **P2 的边界**：如果模型自己改写了上下文（例如工具返回内容里带指令），
   "上下文可复现"是否还成立？——目前成立，因为工具输出也进日志；但要保证**所有**输入都进日志。
