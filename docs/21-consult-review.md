# 外部评审（GPT-6-Astra）：我的分类与反驳

原始回答：`out/consult-20261116-203850.md`（1890 字符 / 6814 tok / 75s）
简报：`docs/consult-brief.md`

我不照单全收。下面按"能立刻做 / 需要验证 / 不适用"分类，并标出我认为它**说错或说过头**的地方。

## 一、它说得最重、也最对的一条

> 最大缺口不是功能，而是没有证据证明"记录的效果"覆盖"实际发生的效果"。

**这条成立，而且是我之前一直含糊过去的地方。**

具体例子：`shell` 工具声明的效果只有 `proc.exec <命令>`。命令内部 `rm -rf /`、
读 `~/.ssh/id_rsa`、`curl` 上传，效果集**一条都不记**。所以"效果集 + 审计"在
shell 这一层只是"我批准了这条命令"，不是"我批准了它做的每件事"。

已做（今天）：
- `ui doctor` 现在直接打印**信任边界**：
  ```
  信任边界（说清楚，不含糊）
    shell   ：获得批准后，命令内部的读写/联网不受效果策略约束
    plugin  ：效果按声明仲裁；声明之外的行为无法拦截
    mcp_call：同上，外部 server 在进程内自主
  ```
- `docs/07-security.md` 增加同样的对照表。

未做（真正解法）：
1. **观测式效果**：shell 执行前后对比工作区 mtime/哈希，把"实际变了哪些文件"
   作为 `effect/observed` 记进日志。我们已经有一半实现（`lab pack` 的 mtime 扫描）。
2. **OS 级沙箱**才能让"不仲裁"变成"不能做"。

## 二、需要验证的三条

| 它的判断 | 我的态度 | 验证方式 |
|---|---|---|
| 3–5 人团队 1–3 个月能复制日志链演示 | 大体同意，但**复制到"可信"更难**（崩溃对齐、旧策略还原） | 无（接受） |
| 团队模式最危险的是"每步成功、整体错误" | 同意，且给了三个具体场景 | 可以设计用例压 |
| 验收被污染（代理改测试让自己通过） | **成立**：我们的 `--accept` 是用户给的命令，但代理能改测试文件 | 加"验收材料哈希"校验 |

## 三、我认为它**说过头**的地方

1. **"哈希链无外部锚点，无法证明整份日志未被重写"**——技术上对，但我们要防的是
   **单步篡改**，不是"整份历史重写"。整份重写需要攻击者同时控制文件系统和我们的
   工具链，那时任何本地审计都失效。把它写成"完全无法证明"是不公平的；正确说法是
   "本地审计不防全量重写，需要外部时间戳/公证"。→ 我们可以在文档里写清这个边界，
   而不是假装有公证。
2. **"砍掉零依赖叙事"**——我同意**不把它当卖点**，但不同意它是负债：手写协议确实
   有风险，可它也换来了"单文件、可审计、无供应链"。保留约束，停止宣传。
3. **"先找三个陌生团队验证参与"**——方向对，但对单人项目来说，更可行的是
   "先让一个陌生工程师在 30 分钟内跑通验证包"。

## 五、它给的最小可信证据集（我采纳成 TODO）

1. 固定版本二进制 + 可重复构建步骤；
2. 一条命令启动的**离线恶意样例集**；
3. 可独立实现的日志格式 + 小型校验器；
4. 外部人员复跑记录（含失败）。

样例需覆盖：删改日志、截短尾部、并发强杀、符号链接逃逸、shell 间接读密钥、
插件漏报效果、合并后验收失败。**每项给出预期退出码与磁盘结果，并明确哪些攻击
当前拦不住。**

这条我认为是这次评审里**最有行动价值**的输出。

## 六、一句话结论

评审没有推翻我们的方向，但**戳破了一个我们一直在暗示的强度**：
"效果集覆盖一切"是假的，"效果集 + 信任边界 + 可重判"才是真的。
补上信任边界的说明（已做）和观测式效果（未做），比再加三个功能重要。
