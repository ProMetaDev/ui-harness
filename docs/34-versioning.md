# 34 · 版本号方案（含 1.0.x 的撤回）

> 结论先说：**我们撤回 `v1.0.0` – `v1.0.2` 三个 tag，改为 `0.2.0`。**
> 原因不是"谦虚"，是评审给出了可验证的反例：一个存在 2 个 P0 安全缺口、
> 未做真实多文件仓库评测、且有 7 项已知遗留的版本，用 1.0 是在给用户错误信号。

---

## 1. 为什么撤回

半年前（好吧，是昨天）我们打 1.0 的理由是"API/契约稳定"。这个定义站不住：

| 1.0 通常承诺的东西 | 我们在 `a294c30` 时的实际状态 |
|---|---|
| 生产可用 | 2 个 P0 安全缺口（密钥可免审批读取、截断参数被静默补全写盘） |
| 接口冻结 | `parse_arguments` 行为在 24 小时内被安全修复改变 |
| 经过外部检视 | 第一次外部评审就推翻（评审自身结论："更接近 v0.2-alpha"） |
| 有真实使用证据 | 0 个外部用户、基准以单文件小样本为主 |

**用版本号表达"我们做完了"是廉价的；用可验证的准入条件表达才不是。**

---

## 2. 新方案

### 2.1 规则

采用 SemVer 的 **0.x 段**，且比 SemVer 更保守：

| 位 | 什么时候动 | 例子 |
|---|---|---|
| `0.MINOR` | **任何不兼容变更**（日志格式、事件字段、CLI 语义、策略默认值）；也包括"这一版重新定义了某个契约" | 0.2 → 0.3 |
| `0.MINOR.PATCH` | 兼容的修复、性能、文档、安全补丁（不改变对外契约） | 0.2.0 → 0.2.1 |
| `0.MINOR.PATCH-alpha.N` | 尚未通过门禁的预发布（CI 红、或含已知未修 P0） | 0.3.0-alpha.1 |

**`0.x` 的语义承诺只有一条**：任何 `0.MINOR` 之间都可能不兼容，升级前看 CHANGELOG 的"不兼容"小节。
我们不承诺 `0.x` 内部稳定——那是 1.0 才有的东西。

### 2.2 我们**不做**的事

- 不为了显得成熟而跳号（这正是这次要撤回的错）。
- 不用 `v1.0.0-rc.1` 这类"准发布"名头，除非 1.0 的准入条件已全部满足——否则 rc 和正式版没区别。
- 不在 tag 上打"最新/稳定"之类标签。

---

## 3. 1.0 的准入条件（可验证，逐条对应命令）

**只有下面 8 条全部为"是"，才允许打 `v1.0.0`。** 写在这里，是为了防止未来又一次"感觉差不多了"。

| # | 条件 | 判定方式 |
|---|---|---|
| G1 | 无已知 P0/P1 安全缺陷 | 最近一次外部评审报告 + 我们自己的 `docs/33` 遗留表，P0/P1 全部关闭；未关闭的必须降级为"已接受风险"并写明理由 |
| G2 | 契约冻结 ≥ 30 天且无破坏性变更 | `git log --since` 查 `ui-core/src/journal.rs` / 事件字段 / CLI 语义的变更；期间只有修复 |
| G3 | 真实多文件仓库评测 | ≥ 10 个真实仓库（≥ 1 万行）的修改/排错任务，成功率、步数、token、观测开销有数据；脚本在 `tools/`，报告在 `docs/` |
| G4 | 至少 3 个外部使用者（非作者） | 能说出他们用在哪、跑多久；不是 star 数 |
| G5 | 双平台实机验证 | Linux 与 Windows 上各跑一次完整门禁 + 一次真实模型会话；Windows 需 MSVC 与 mingw 各一次 |
| G6 | 安全边界有第三方复核 | 至少一次独立安全评审（可复用 `docs/33` 的形式），且其结论为"无 P0/P1 未决" |
| G7 | 记忆/知识 P2 完成或明确移出 1.0 范围 | 二选一，不能含糊 |
| G8 | 文档与代码零失步 | `docs/31` 的数字、状态、命令全部由脚本产出或可一键校验 |

`tools/tag.sh` 增加一道闸：打 `v1.*` 时若 `docs/34-versioning.md` 里没有
`1.0-就绪: 是` 这一行，直接拒绝。**规则要被工具执行，否则只是口号。**

## 4. 撤回记录（信息不丢）

| 旧 tag | 指向提交 | 处置 | 新 tag | 说明 |
|---|---|---|---|---|
| `v1.0.0` | `cfa6bf0` | 删除 | `0.1.0`（历史节点，可不打） | 内核首个可用原型 |
| `v1.0.1` | `b00d7ea` | 删除 | — | UI 收尾 + 事件接线 |
| `v1.0.2` | `4a03b64` | 删除 | **`0.2.0`** | 外部评审 P0/P1 修复后的第一个版本 |

提交本身不会被删除——`git log` 里都能查到。tag 只是**给版本贴的标签**，
标签贴错了就该换，留着错的标签才是对用户不负责。

如果某个旧 tag 已经被别人引用（目前没有），我们会保留它并加注 `-withdrawn` 后缀，
而不是悄悄删掉。
