# 差距分析（2026-11-16）

先把"我们知道自己多少分"这件事说清楚——**三个数字，可信度完全不同**：

| 数字 | 来源 | 可信度 |
|---|---|---|
| **65.6/81** | 第三方静态审计给 DSH 的分 | 独立评审，±3 噪声 |
| **≈67.5/81** | 我们照同一套 42 条标准自评 | **自己打分**，可能偏乐观 |
| **21/21** | 我们自己实现的 T1–T7 契约测试，真跑 | 真实进程，但**尺子是我们自己做的** |

结论先说：**契约层我们是第一梯队，能力层差一档，工程层差得最远。**

## 一、契约层（能不能被程序驱动）

T1–T7 实跑 21/21，Windows 上真模型 + serve 都通了。这块**不是估算，是证据**。
但同口径下 DSH 也拿 20/21，所以这是**并列第一梯队**，不是领先。

## 二、能力层：和 DSH 逐项比

| 维度 | 我们 | DSH | 差距性质 |
|---|---|---|---|
| 工具数 | **13**（含 MCP/插件网关） | 20+（含 LSP、浏览器、computer-use） | 数量差可补，LSP/computer-use 我不建议追 |
| 会话 | **单日志**，无列表/切换/恢复 | 437 个会话相关路径，多会话是核心体验 | **最硬的缺口** |
| MCP | 只有 tools，stdio | tools + **resources**，客户端是独立包 | 差 resources 与 schema 透传 |
| 多 provider | 注册表 + 每轮切换 | 60+ provider + 订阅 OAuth + profile 隔离 | 差 OAuth 与凭据隔离 |
| 技能 | 加载机制有，无内置库 | `agent-preset/skills/*` 有整套模板 | 差内容，不差机制 |
| 记忆 | **无** | 有 memory 包 | 结构性缺失 |
| 沙箱 | 工作区边界 + 效果策略，**无 OS 沙箱** | bwrap/Landlock/Seatbelt/Win token | 安全纵深差一层 |
| 审计 | 哈希链 + 血统 + 结论对账 | **未见等价机制** | **我们领先** |

## 三、证据层：我们缺的不是功能，是"证明"

| 我们声称 | 现有证据 | 缺什么 |
|---|---|---|
| 崩溃不丢数据 | 单进程测试 + 10 写者压测 | 没有长时间浸泡（soak）测试 |
| 隔离可合并 | apply 的冲突/漂移闸有测试 | 没有多代理真实并发冲突的样本 |
| 团队模式可用 | 真模型跑过 4 次（3 矩阵 + 1 修复后） | 样本太小，失败模式未知 |
| 成本可控 | 有账本与 token 统计 | **没有跨任务的成本基准** |
| 可审计 | 哈希链、verify、对账都有测试 | 没有"篡改→检测"的外部复现指南 |

## 四、工程层：差得最远的一层

| 项 | 状态 |
|---|---|
| 分发 | 无安装包、无版本 tag；Windows 二进制靠手工交叉编译 |
| CI | **无**（门禁只能手跑） |
| 文档 | 18 篇，但**没有一篇面向使用者**（全是设计/复盘） |
| 许可 | Apache-2.0 已加，但没在 README 里说明 |
| 观测 | 有日志，无指标/追踪导出 |

## 五、按"阻塞什么"排序

## 六、三条判断

1. **不要为了分数补功能**。我们自评 67.5 已经超过 DSH 的 65.6，但那是自己打分。
   真正缺的是**外部能用的东西**：会话、安装、CI。
2. **审计优势必须主动证明**。它不在任何基准的评分项里，没人会替我们发现——
   需要一篇"篡改→检测→复现"的公开说明，最好带可跑脚本。
3. **团队模式是差异点但证据最薄**。4 次真模型跑通，不知道失败边界在哪。
   再用 3 个更难的任务压一次，比加 3 个功能更有价值。
