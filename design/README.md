# UI 的 UI：飞行记录仪

这是一份**独立设计原型**，不是生产文件。生产壳仍在
[`ui-cli/assets/chat.html`](../ui-cli/assets/chat.html)；另一个对话在改内核，这里不碰它。

先看[改造前后对比](compare.png)。打开 [`ui-concept.html`](ui-concept.html) 即可点（单文件、无外链、离线可跑）。

## 一句话方向

**现在的网页端是「通用聊天 + 一个小账本」；应该变成「飞行记录仪 + 一个对话区」。**

产品的差异点不是聊天，而是**每一步可解释**：模型看到了什么（快照分段）、
它想做什么（效果）、谁放行的（决策）、花了多少（账本）、怎么复现（实验包）。
这些现在被塞进右侧一张 288px 的 kv 表里，视觉上又用了蓝白 SaaS 的通用语言。

新方向把三件事提到第一层：

1. **对话是日志，不是气泡。** 时间 / 角色 / 工具 / 决策共用一条时间线；
2. **右栏是「当前步」仪表。** 快照分段 + 决策时间线 + 账本 + 审批队列；
3. **审批永远在视线内。** 不藏在滚动区里，固定在输入框上方。

---

## 三个具体决定

### 1. 暗色为默认，琥珀是唯一的强调色

沿用 TUI 的色板（`#12140f / #e8e6df / #d99a3c` 的网页版本），让终端和网页像同一个产品。
明色不是另做一套组件，只是同一组语义 token 换映射：暖纸底、深琥珀，像审计底稿。

规则：**强调色只出现在「当前焦点 / 可操作」上**；成功、警告、拒绝只用于状态 chip，
不用来装饰。蓝色被彻底移除——它会让产品看起来像另一家 SaaS。

### 2. 右栏从「账本」升级为「当前步」

```
06  CURRENT STEP
    ● 等待批准

CONTEXT                     1,719 tok · 6.8 KB
[███▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌]  ← 分段条
core     kernel    520
env      kernel     96
tools    tools     246
history  session   782
skills   skill      75

DECISIONS
● fs_read  allow   匹配 fs.read ** · 12ms
● fs_edit  allow   匹配 fs.write demo/** · 9ms
● shell    ask     proc.exec cargo test · 等待

BUDGET
tokens  1,719 / 200k   [▁]
calls   3 / 60         [▁]
wall    12s · $0.000

APPROVAL QUEUE 1
shell · proc.exec · cargo test --offline
```

数据来源是内核的 `Hooks::on_snapshot` / `on_decision`——和写 journal 同一处，
不是前端自己猜。**放不下时从最旧的决策开始丢，并明写「更早 N 条」；账本贴底。**

### 3. 审批固定，不随对话滚走

审批是「现在必须做的决定」，不是历史记录。所以它固定在输入框上方：

```
需要批准 · shell · proc.exec
cargo test --offline · cwd demo · timeout 120s · 300s 后按拒绝处理
[允许一次 Y] [总是允许 A] [拒绝 N]
```

对话区里只留一句「需要执行命令，先要你批准」，不再放一张会被滚掉的大卡片。
右栏的「审批队列」只负责告诉你有几个待办。

## 版式

```
┌────┬──────────────┬──────────────────────────────┬──────────────────┐
│ 64 │ 272          │ 1fr                          │ 344              │
│ 活 │ 会话         │ 顶部：标题 / 路径 / 模型 / 模式 │ 当前步           │
│ 动 │ 上下文       │                              │ 快照分段         │
│ 栏 │ 操作         │ 日志（时间 / 角色 / 工具）    │ 决策时间线       │
│    │              │                              │ 账本             │
│    │              │ 审批条（固定）                │ 审批队列         │
│    │              │ 输入框                        │                  │
├────┴──────────────┴──────────────────────────────┴──────────────────┤
│ 26  状态栏：模式 / 模型 / 工作区 / 链校验 / tok / calls / cost / 时间 │
└─────────────────────────────────────────────────────────────────────┘
```

版式规则：

| 规则 | 值 |
|---|---|
| 栅格 | 4px 基准；栏宽 64 / 272 / 1fr / 344；状态栏 26px |
| 圆角 | 工具行/卡片 6px，按钮 5px，输入框 8px；不再用 12–16px 的大圆角 |
| 边框 | 1px `--line`；能用线分层的不用阴影 |
| 字体 | 正文 14px/1.78 无衬线；数字、路径、ID 用等宽 |
| 标签 | 9.5px 等宽大写，字距 .16em |
| 行高 | 日志条目 22px 间距；工具行两行（第一行身份/效果/决策，第二行结果） |

色板（暗）：

| 角色 | hex | 用途 |
|---|---|---|
| 背景 | `#0b0d10` | 画布 |
| 面板 | `#12161b` | 工具行、输入框、卡片 |
| 分隔 | `#232a33` | 1px 线 |
| 正文 | `#ece9e0` | 模型/用户正文 |
| 次要 | `#8f8d83` | 时间、路径、说明 |
| 强调 | `#e3a24b` | 当前焦点、主按钮、版本标记 |
| 成功 | `#8bc49a` | allow / chain ok |
| 拒绝 | `#de7a66` | deny / error |

明色把背景换成 `#f4f1e9`，强调换成 `#a8631f`，语义不变。

## 空状态：Pre-flight

不再是一个居中的 logo 和三个胶囊按钮。空状态回答三件事：

- **能做什么**：办公 / 代码 / 创作，每条给一个真实例子；
- **这个工作区是什么**：模型、journal、skills、tools、预算；
- **最近做过什么**：三条最近会话，直接续上。

右栏是 workspace readiness，而不是「当前步」。UU 只在空状态出现一次，
在 `PRE-FLIGHT` 旁边眨眼——严肃时刻不卖萌。

## 实验室：文档，不是日志

实验包是产品最像「科研工具」的地方。所以主区变成一篇可读的文档：

- 顶部：实验名、seed、时间、自洽 badge；
- 指标卡 + 校验卡（产物哈希 / 输入一致 / 结论对账 / 日志链）；
- 产物表：`sha256 / bytes / producedBy`；
- 输入血缘与结论对账；
- 复现命令。

右栏在实验室里收起，把宽度让给文档。顶栏换成 `python 3.11 · 校验 · 导出`，
不显示对话的模型/模式。

## 如果只做三件事

按投入产出排序，建议先做 P0：

| 优先级 | 改动 | 为什么 |
|---|---|---|
| **P0** | 换 token（暗色 + 琥珀 + 暖灰），去掉蓝色和大圆角 | 一天内能改完，气质立刻从 SaaS 变成工具 |
| **P0** | 右栏接 `on_snapshot` / `on_decision`，做分段条 + 决策时间线 | 这是产品独有的信息；现在被 kv 表浪费了 |
| **P0** | 审批条固定到输入框上方 | 审批不该滚走；这是可用性问题，不只是审美 |
| P1 | 聊天气泡改日志（时间/角色栏、工具两行、效果/决策 chip） | 信息密度和「可回放」的叙事感 |
| P1 | 空状态改 pre-flight + workspace readiness | 首屏现在太空，且没告诉用户工作区是什么 |
| P2 | 实验室文档化 | 差异化最大，但可以晚一点 |

## 还没定的

- UU 在明色下是否仍然用琥珀？现在只在空状态出现。
- 344px 右栏在 1280 笔记本上是否太宽？1300 以下原型会收起右栏。
- 移动端只做了「侧栏/右栏收起」，没有专门排布。
- 日志的「工具行两行」在窄屏会变成三行，需要再看。
- 生产 `chat.html` 是单文件内嵌 CSS/JS；移植时建议先抽 token，再换右栏，最后动日志。
